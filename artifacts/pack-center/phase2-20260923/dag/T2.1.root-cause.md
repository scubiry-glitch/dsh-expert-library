# T2.1 Root Cause — silent exit-0 of isolated dsh instance

## Symptom
`DSH_HOME=/tmp/p2-20260923/dsh-a node /usr/lib/node_modules/@deepseek-ai/dsh/lib/bin.js --profile p2-a --host 127.0.0.1 --port 18281 --no-open` exited 0 in ~0.3 s, printed nothing, never listened. `--dump-config` printed 0 bytes (also exit 0). In-process `runProfile(...)` probes did mount a tree, which wrongly pointed suspicion at plugin resolution / composition.

## Root cause
`lib/bin.js` ends with:

```js
if (import.meta.main) await runCli();
```

`import.meta.main` is **not implemented in Node v20.20.0** (`/usr/bin/node` here): the expression evaluates to `undefined`, so `runCli()` never runs. The process parses nothing, prints nothing, and drains with exit code 0. Verified: under node20 even `dsh --version` and `dsh --profile p2-a --dump-config` produce zero bytes with exit 0; a preload hook showed no `process.exit` call and `beforeExit` with only stdio handles at ~140 ms.

The production instance runs under **Node v22.22.0** (`/root/.nvm/versions/node/v22.22.0/bin/node`, per its /proc cmdline — read only), which does implement `import.meta.main`. That is why production works while every isolated launch with the default `node`/`dsh` (shebang `#!/usr/bin/env node` → /usr/bin/node) silently no-oped. The prior P5/P6 two-instance probe succeeded because it also ran under an environment where the CLI actually executed.

Secondary notes (not causes): composition and plugin resolution were always fine — `loadProfile` returns all 3 bundle layers (base, web-app, expert-library) and `import('@zhijian/dsh-expert-library')` resolves from the profile dir through the exact symlink. The `/manage/center` prefix alone has no GET route (400 CENTER_INVALID_REQUEST); the status projection is `/manage/center/connection`.

## Fix (no DSH core changes)
Launch with the node22 binary explicitly:

```
cd /tmp/p2-20260923/workspace-a
DSH_HOME=/tmp/p2-20260923/dsh-a setsid nohup /root/.nvm/versions/node/v22.22.0/bin/node --max-old-space-size=1536 /usr/lib/node_modules/@deepseek-ai/dsh/lib/bin.js --profile p2-a --host 127.0.0.1 --port 18281 --no-open </dev/null >>/tmp/inst-a.log 2>&1 &
```

(same for B with dsh-b/p2-b/port 18282). `scripts/phase2/run-ab-instances.mjs` was updated to spawn the node22 binary directly instead of relying on PATH `dsh`.

## Verification
- Both processes alive (pids in T2.1.instances.json).
- `curl -H 'X-Pack-Center-UI: 1' .../manage/center/connection` → HTTP 200 `{"ok":true,"data":{"configured":false,...,"connection":null}}` on both ports.
- Without the UI header: HTTP 403 `CENTER_UI_REQUIRED` (guard intact).
