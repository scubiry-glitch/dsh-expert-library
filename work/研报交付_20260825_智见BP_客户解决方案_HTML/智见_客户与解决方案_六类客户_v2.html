SEC.01

客户一 · 中央部委

CENTRAL MINISTRIES
一页结论

政府端定位为示范与标准入口，不纳入近期收入主战场——先立标准、后收钱；部委把贝壳口径纳入工作流之日，就是替换成本最高之时。

① 需求痛点 PAIN POINTS
口径不一、更新滞后全国市场监测依赖地方报送 政策效果缺可核验底稿 数据分散住建 · 统计 · 自然资源 · 金融各部门

SEC.02

客户二 · 地方监管

LOCAL REGULATORS
一页结论

地方监管是标准入口的放大器——一个省跑通、全省复制；政府端先立示范，收入锚定后续国企收储与银行风险两个灯塔。

① 需求痛点 PAIN POINTS
区县口径对齐难 小区级价格缺失 舆情与价格监测手段弱 40 城 vs 50 城口径要向领导解释

SEC.03

客户三 · 金融机构

FINANCIAL INSTITUTIONS
一页结论

定价纪律（内部口径）：把「可审计」翻译成银行的 KPI——银行年费 1000 万起、3000 万为合适锚（目标假设）；首单让功能不让价格、按机构分档、先签年度。边界声明——仅提供价值参考与监测信号，不替代法定评估、不直接决定授信或减值计提。

① 需求痛点 PAIN POINTS
单点评估＋贷后放任估值与市场存在时滞 压力测试缺统一口径区域 / 物业类型 / 客户集中度 评估报告不可复现内审、监管检查无法还原 签章责任重结论出错责任界面不清
② 贝壳解题思路的不同 · T0 → T+N WHAT WE DO DIFFERENTLY
T0 · 授信时点估值参考时点
  • 房源级估值区间＋置信度
  • 与外部评估报告差异自动比对
  • 按数据 / 方法 / 假设三分归因
→ 形成授信参考底稿
→
T+N · 贷后监测持续
  • 持续更新估值
  • 价值偏离预警
  • 组合压力测试
→ 自动生成贷后复核底稿
→
复核底稿 · 可审计输出
  • 价值台账持续可查
  • 同条件可复现、内审问询一键还原
  • 直接供内审与监管检查查验
持续需求，而非项目制
做底稿、不做签章

估值只做过程、不做结论；需盖章环节引入持牌评估机构协作——不抢法定评估刚需，分润补位、责任界面清晰；一次估值偏差的成本远高于系统年费。

③ 产品优势 PRODUCT EDGE

差异归因三分

偏差按数据 / 方法 / 假设可解释、可追溯——而非「两个数打架」。

ADV · 02

ADV · 03

贷后复核底稿直接供内审与监管检查查验。

SEC.04 ★

客户四 · 保租房国企 / 城投 / 住房运营平台

KEY PAGE · STATE-OWNED HOUSING
一页结论

收储本质是把存量蓄水池的水引向保租房源头活水；定价底稿化后，1000+ 收储主体（口径：STAID 分层汇报大纲）的决策将从经验走向数据——左海已交付、萧山环投在谈、贵州 / 辽宁复制。边界：输出「价值参考与监测信号」，不替代法定评估。

① 需求痛点 PAIN POINTS
项目筛选靠经验口径不一 测算缺统一口径收储价格 · 租金 · 改造成本 · 运营成本 政策目标 × 社会效益 × 经营安全难兼顾 历史假设难还原审计巡视追问「当时为什么这么决策」
② 贝壳解题思路的不同 · 因果可解释估值框架 EXPLAINABLE VALUATION

SEC.05

客户五 · 开发商

DEVELOPERS · S-LAYER
一页结论

「可复核底稿」的付费意愿已被验证（福州左海集团收储估值咨询：历史指数修正后单套价格低约 10%、客户已续约，详见客户四）；开发商线待两灯塔形成合同与复购后作为标准化扩展铺开——先慢后快，不补贴换规模。

① 需求痛点 PAIN POINTS
依赖经验判断与外部研报拿地 · 定价 · 去化 投后复盘无底稿当初为什么这么定价、基于什么数据与假设，事后无法还原
② 贝壳解题思路的不同 WHAT WE DO DIFFERENTLY
中指 / 克而瑞 · 榜单式服务
指数排行 ＋ 报告订阅交付物是报告，结论不绑定假设
→
智见 · 交付物形态不同
可复核底稿来源 · 口径 · 假设 · 版本全程留痕
条件化推演结论绑定假设——不同假设下结果怎么变
土地供给土地成交 / 批售
→
新房供应取证 / 供应节奏
→
库存可售存量
→
去化去化周期 · 连成链条
三个交付形态 城市监测订阅CLI / 客户端 / API 标准组件，替代「买报告」，嵌入开发商数据工作流 开盘定价支持条件化解释：不同去化假设下价格如何表现 投后复盘底稿决策时能追溯、复盘时能还原
③ 产品优势 PRODUCT EDGE
ADV · 01

城市地图与客研数据

贝壳自有成交 / 带看全链路数据（口径：贝壳授权数据），房源—楼栋—社区—项目级颗粒度。

ADV · 02

CLI / API 标准化嵌入

政研通 CLI 已跑通（Python＋TS 双版本，口径：2026-08 交付记录），支持批量城市比较与底稿导出。

ADV · 03

条件化定价不担责

假设框定＋边界声明，责任界面清晰——不承诺结果、不做趋势性判断。

④ 产品组合 订阅城市监测订阅（CLI＋API） 定价开盘定价支持模块 土地土地供给与去化分析 复盘投后复盘底稿
⑤ 交付团队 数据城市数据团队 集成API / 集成工程师 研究行业研究顾问
SEC.06

客户六 · C 端个人

CONSUMERS · LONG-TERM
一页结论

C 端价值不在当期收入，而在建立「研究可信」的口碑与数据入口，为远期 Agent 沉淀用户信任与使用习惯；待两灯塔形成合同与复购后再启动，不抢跑。

① 需求痛点 PAIN POINTS
信息不对称真实成交、挂牌价与营销话术难区分 中介话术不可验证买卖 / 置换 / 租金判断缺少可复核依据
② 贝壳解题思路的不同 · 三层分析框架 WHAT WE DO DIFFERENTLY
城市
周期与供需——城市层判断大势
板块
配套与流动性——板块层选地段
房源
成交 · 挂牌 · 租金——房源层落点
贝壳真房源

解决「房源是真的」——智见不替代真房源、不与它比拼信息真实。

诸葛找房 / 兔博士

轻量工具，解决「查得快」——智见不比拼轻量查询。

智见 · 判断是可验证的

研究过程可追溯、假设可调整、口径可解释——结论有条件、历史可复现。

三个机制 个人不动产研究 Agent（远期）城市—板块—房源三层分析＋收入 / 首付 / 月供 / 持有周期测算 条件化分析输出「不同假设下的结果」，不输出「必须买 / 必然涨」（红线：不做趋势性判断） 指标解释租金回报率 / 挂牌成交比 / 去化周期，每个指标带口径与适用边界
③ 产品优势 PRODUCT EDGE
ADV · 01

可验证的研究过程

结论有条件、假设可调整、历史可复现。

ADV · 02

三层分析框架

城市（周期与供需）→板块（配套与流动性）→房源（成交、挂牌、租金）。

ADV · 03

家庭现金流测算
