## 零、执行摘要（结论先行）

**开发商侧：新政把开发商从"买家"变成"被分析对象"。** 付费能力在缩表（开发投资累计同比 -19.2%、销售面积 -11.8%，Wind EDB，2026-07），且开发商属于三层付费者中的"显性付费者"——旧利润就是制度租金，租金随制度取消（v5.4 总结）。因此开发商侧的机会卡，**付费方不在开发商，而在整合者（并购买方）、收储方（政府/国企）、银行（贷后与好房子评审）**；开发商是数据标的物与协同方。真正可服务的是四件事：并购尽调前筛、存量土储处置、好房子品质定价、项目化合规下的投后复盘。**结论：开发商线不是收入主战场，是数据生态位**——战略意义在"被分析对象的项目样本与数据授权"，收入借道客户三/四。

**C 端侧：新政把"选择风险"制度化地交给购房者（延期付费者，红线=强制预算约束），C 端第一次有了刚性信息需求——但付费方不是购房者。** C 端付费意愿历来薄弱，全部机会卡走"引流/生态内嵌/信任资产"，不编独立收费。三个真需求：红线合规可贷能力测算、卖旧买新置换决策沙盘、项目交付风险提示（含存量期房"滞留乘客"监测）。**结论：C 端价值不在当期收入，在数据入口+口碑+信任**——服务业的核心是信任，信任换转化，为远期 Agent 铺路（客户六原有定位不变，新政只是给了更具体的内容）。

**总判断：开发商+C 端是飞轮不是发动机。** 两灯塔（收储工作台、银行风险工作台）仍是收入发动机；本线两张高优先卡（并购前筛、置换沙盘）付费方明确、杠杆最强，其余做生态位与信任。先慢后快，基础不牢地动山摇。

## 一、开发商侧：机会扫描（4 张机会卡）

**研判框架**：新政三条主线对开发商的重写——杠杆被拆（第三章：项目封闭水池）、土储变包袱（缴地价贷款全链条禁止）、并购重组成真主角（第四章：封闭账户=实时真实项目报表，尽调成本骤降）。三条线共同指向：**开发商相关的智见机会，需求端在"围绕开发商的交易与处置"（并购、收储、评审），不在开发商自身的管理需求**。诚实口径：开发商的报告/榜单预算随制度租金一起收缩（中指/克而瑞式榜单服务的缩表压力同源），智见若对开发商卖"订阅报告"，是与缩表赛跑；对整合者/收储方/银行卖"围绕开发商的数据服务"，是与制度同向。

### 机会卡 D1：并购尽调前筛——项目级市场画像（开发商侧最高优先级）

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 第四章：并购重组是资本市场文件的真主角；项目封闭账户=实时、真实、第三方托管的项目报表，尽调成本骤降；证监会文件"基于项目"发行准入。谁把"项目级真实报表"最先转化为整合能力，谁定义出清后结构 |
| ② 需求 | 整合者（头部房企、建筑央企、AMC、外资特殊机会基金——第十二/十三章进场名单）需要低成本项目级筛选：先筛后尽调。市场侧数据（去化、价格、带看、库存、土地成本追溯）是尽调第一层漏斗；被并购标的需要"卖得掉"的定价参照 |
| ③ 智见机会 | 项目级市场画像卡（区位供需、去化速度、价格趋势、竞品对照、拿地成本追溯），输出尽调前筛底稿（做底稿不做签章，沿用四本账）。**边界诚实**：主办行专户流水是"账户级的真"，贝壳数据只是"颗粒度更粗的补充真"（v5.4 第九章）——定位是"第一层漏斗、缩小尽调范围"，不替代主办行数据、不替代法定尽调 |
| ④ 贝壳生态杠杆 | 贝壳成交/带看/挂牌数据底座（房源—楼栋—社区—项目颗粒度，客户五源稿口径）+ 政研通自爬网签/土地数据 + CLI/API 标准化交付（Python＋TS 双版本，2026-08 交付记录） |
| ⑤ 变现形态 | **整合者付费**：项目画像订阅+尽调前筛报告（对齐客户三金融机构年费逻辑，单价可低一档）；开发商侧免费/低费——换数据授权与标的露出。买方付费、卖方引流 |
| ⑥ 验证锚与时间窗 | 2026Q4 白名单贷款覆盖率与并购审批节奏（失灵⑤并购通道容量）；2027H1 并购案例中"数据前筛"被采用 1-2 例即算验证。风险：失灵③数据断供——若"银行→市场"数据不共享，尽调重回关系网络，市场画像价值降级为参考 |

### 机会卡 D2：存量土储处置决策底稿（退地/转让/被收储）

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 第三章：土储从融资工具变回纯成本项，"以地融资"通道全断；历史高价地存货减值与"被动退地"先于新项目竞争出现。客户四收储工作台的政策同源——收储是土储的制度化出口之一 |
| ② 需求 | 开发商滞留土储的处置决策：退地 vs 转让 vs 被收储；地方政府/国企收储定价（左海案例：历史指数修正后单套低约 10%、帮买方省数千万——客户四口径）；处置决策需要可复现底稿应对审计与国资追问 |
| ③ 智见机会 | 土储价值重估底稿（历史拿地成本×当前市场价×时间成本×处置路径比较），对接主 A 收储工作台的八步闭环/四本账体系复用；开发商侧作为"被收储方的定价对账服务"——争议调解的底稿化 |
| ④ 贝壳生态杠杆 | 土地市场自爬数据（成交面积/楼面价/流拍率/溢价率，STAID 关键输入口径）+ 收储工作台（1000+ 收储主体，STAID 口径）的地块测算模块扩展 |
| ⑤ 变现形态 | 主场景是**客户四（收储方）付费**，开发商侧机会是收储定价争议的调解底稿，低费或随收储交易打包；独立卖给开发商仅限个别有处置预算的主体，不设收入预期 |
| ⑥ 验证锚与时间窗 | 收储贴息落地（约 3 万亿、100-200 万套，测算口径）与 2027H1 收储放量节奏；土储处置模块在收储工作台内的使用数。此卡随主 A 放大，不单独启动 |

### 机会卡 D3："好房子"信贷分层下的品质定价支持

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 开发贷办法 13/14 条：优先支持"好房子"项目——品质供给第一次与利率、额度分层挂钩；v5.4 第十三章："谁认证、什么标准、如何挂钩，是 2027 年最值得跟踪的执行点" |
| ② 需求 | 开发商需要"好房子"认证准备与品质溢价测算（品质投入→信贷红利+售价溢价的 ROI）；银行需要"好房子"的客观验证（不能只凭申报材料）——这正是 I 标尺层"好房子"品质锚（中房协标准）的用武之地 |
| ③ 智见机会 | 品质溢价数据支撑：用贝壳数据（户型/物业/配套/成交溢价/去化速度）构建"好房子"可验证画像；联动中房协标准沉淀行业共识（I 标尺层既有设计）；条件化推演"不同品质等级下价格与去化如何表现" |
| ④ 贝壳生态杠杆 | 中房协合作（标准与方法论，STAID 口径）+ 贝壳房源品质数据 + 家装生态（"好房子"带动存量翻新，第九章第二三曲线同向） |
| ⑤ 变现形态 | 对**银行（客户三延伸：好房子项目甄别）与标准制定方（客户一/二延伸：标准数据支撑）收费**；开发商侧仅作标准咨询增值，不设独立收费预期 |
| ⑥ 验证锚与时间窗 | 2027 年"好房子"认证细则出台；**开发贷利差是否出现分项目评级的可观察分层**（v5.4 总结：定价维度检验信号——不是拒贷配给，是利差分层）；若有银行将品质画像纳入项目评审即为验证 |

### 机会卡 D4：项目化合规下的投后复盘底稿（标准化扩展，轻订阅）

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 第三章：项目单独建账、资金不得混同、不得划拨集团/关联方、回款先还贷——开发商被强制"项目化管理"，复盘从可选项变必选项；现房化把项目周期拉长 2-3 年，复盘周期更长、底稿价值更高 |
| ② 需求 | 开发商的投后复盘（当初为何这么定价、基于什么假设）在新政下的审计与监管检查频率上升；期房转现房进程中，开盘定价支持升级为"现房/期房双轨定价"（期房-现房价差收窄至 5% 以内为辅锚，v5.4 预言） |
| ③ 智见机会 | 现有客户五定位（可复核底稿+条件化推演）直接对接新政需求；土地供给→新房供应→库存→去化链条（客户五源稿）在新政下有了制度性刚需背书；条件化定价不担责、责任界面清晰 |
| ④ 贝壳生态杠杆 | CLI/API 标准化组件（Python＋TS 双版本已交付）+ 政研通数据工作流嵌入；S 层标准化扩展（客户五源稿定位：待两灯塔形成合同与复购后铺开） |
| ⑤ 变现形态 | 标准化低门槛订阅——**开发商付费能力缩表，定位 S 层扩展、不设大合同预期**；主要价值在生态协同（数据换数据）与两灯塔后的扩展弹药 |
| ⑥ 验证锚与时间窗 | 期房占比下降斜率（三年内降至三成以下、中位约 45-55%，v5.4 预言）决定现房定价需求强度；2027 年审计趋严则订阅意愿上升；轻量验证：客户五订阅数 |

**开发商侧诚实评估**：四张卡中 D1/D2/D3 的付费方分别是并购方、收储方、银行/标准方——开发商是数据标的与协同方；D4 是轻订阅但预算缩表。**开发商线不做收入预期，做数据生态位**：谁掌握了"围绕开发商"的市场侧数据服务，谁就站在并购、收储、评审三个制度窗口的交汇处。

## 二、C 端侧：机会扫描（4 张现期卡 + 1 张远期卡）

**研判框架**：新政把"选择风险"交给购房者（v5.4 总结：延期付费者；50%/60% 红线是强制预算约束——既是保护，也是收缩），叠加量的修复先于价（全国二手 -6.3→-5.4 连续 5 个月收窄，北京 -8.7→-4.5 且销售面积 5 月转正，S2707425/S0147146 口径），C 端第一次有制度化的信息需求。但**付费方不是购房者**：是平台（转化与信任）与银行（合规获客）。全部现期卡走引流/生态内嵌，不编独立收费——宁可写引流，不编收费。

### 机会卡 C1：红线合规可贷能力测算器（C 端最高优先级）

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 个贷办法 10 条：月供收入比 ≤50%、全债务支出比 ≤60% 硬红线；13 条：期限最长 40 年（月供 -15%、总利息 +39%、同等月供能力本金上限 +17.5%，测算口径：100 万/3.06%/等额本息）；第十三章：公积金与组合贷如何计入红线——**最大缺席，计入方式未定** |
| ② 需求 | 购房者第一次需要精确测算"我能贷多少"：红线按收入认定执行、一线刚需首当其冲；银行将第一次依法"保护性拒贷"——被拒一次就是记录+时间损失，测错成本高 |
| ③ 智见机会 | 红线合规测算：收入/债务/首付/期限 → 可贷上限、月供、30 年 vs 40 年对比、全债务口径（含公积金组合贷情形，**计入方式未定处明确标注、不编结论**）；比现有月供计算器多一层"合规边界"——结论带口径、假设可调整、历史可复现 |
| ④ 贝壳生态杠杆 | 贝壳 APP 贷款计算器入口升级（高频工具位）+ 经纪人触点（带看前测算、减少无效带看）+ 银行合作渠道（合规获客）——C 端工具、银行付费的桥 |
| ⑤ 变现形态 | C 端免费（引流+信任）；**银行侧**：预审参考数据/获客（合规范围内，对齐客户三）；经纪人端：工作台工具提升效率。C 端本身不收费 |
| ⑥ 验证锚与时间窗 | 工具上线后使用量与留资转化（内部指标）；公积金计入细则出台后测算准确率；若银行采用为预审参考即进阶验证。时间窗：随 2026Q4-2027H1 按揭止跌观察（止跌概率 55-60%，v5.4 传导时序） |

### 机会卡 C2：置换决策沙盘（卖旧买新）——贝壳核心场景的增值

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 个贷 20 条带押过户（单笔省约 4.5 万元：300 万贷款、30 天过桥、日万五，测算口径；省 15-30 天）+ 24 条存量利率置换 + 第十三章第 7 类（卖旧买新存量业主：交易成本改写、改善链加速）；第九章：摩擦下降理论上提升均衡换手率 10-20%（必要不充分条件） |
| ② 需求 | 存量业主置换决策：先卖后买 vs 先买后卖、带押过户流程、利率置换收益测算、时间线规划。单笔 4.5 万的真实成本差异让"算得清"第一次有价值；**注意"卖亏"情形必须能处理**——量的修复不等于价转正（-5.4% 仍深度负增长），诚实的工具才能建立信任 |
| ③ 智见机会 | 置换决策沙盘：卖出估值区间 × 买入标的 × 税费 × 带押过户节省 × 利率置换收益 → 置换净成本与最优路径；结论绑定假设、可复现、可调整（客户六三层框架：城市—板块—房源 + 家庭现金流） |
| ④ 贝壳生态杠杆 | **贝壳最核心交易场景**：卖房入口（我的房源）+ 买房搜索 + ACN 经纪人协作网络——置换是 ACN 天然的协同场景；带押过户正是"通道费换服务费"转型方向（第九章：三刀切金融化收入、服务费承接） |
| ⑤ 变现形态 | 不独立收费——作为交易服务增值（提升置换成交率与佣金场景）；经纪人端工具提升作业效率；换手率提升的受益者是平台整体交易量 |
| ⑥ 验证锚与时间窗 | 北京个案持续性（-8.7→-4.5、销售面积 5 月转正）与全国扩散（-6.3→-5.4 收窄斜率）；带押过户落地城市数与单量；置换客群转化率提升即验证。时间窗：2026Q4-2027H1 |

### 机会卡 C3：项目交付风险提示（现房/期房选择）

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 第一章：交付风险→选择风险（放款后置到竣工备案、现房化挤出效应）；预言：期房销售占比三年内降至三成以下（中位约 45-55%）；37 条新老划断：存量期房"滞留乘客"交付风险不变甚至恶化（第十二章） |
| ② 需求 | 购房者选项目时的交付风险识别：开发商资金健康度、项目进度信号、现房 vs 期房选择与价差判断；**滞留乘客**（已签约存量期房业主）的交付焦虑与信息真空 |
| ③ 智见机会 | 交付风险提示（公开信息整理：开发商历史交付记录、项目去化速度、价格异动、带看热度异常、预售资金监管公开信息）——**定位"风险提示不是风险评级"**：专户流水在主办行，贝壳只有"补充真"（第九章），不做结论性判断、不做趋势承诺（红线纪律）；现房/期房价差与选择辅助 |
| ④ 贝壳生态杠杆 | 房源页/小区页嵌入提示位 + 真房源体系（真房源是底线不是卖点——交付提示是底线之上的信任增量）+ 经纪人口径培训（防止话术与提示冲突，服务品质标准化的落点） |
| ⑤ 变现形态 | 纯引流/信任资产，不收费；转化到现房/准现房项目分销（放款后结佣模式——第九章：现房去化渠道，佣金结算周期拉长但方向与政策同向） |
| ⑥ 验证锚与时间窗 | 提示位使用率与投诉率；预售资金监管披露进展（若监管账户信息向公众开放——知情权再分配的后半程——此卡升级为强需求，**时点存疑、不拔高**）；期房占比下降斜率决定需求强度 |

### 机会卡 C4：存量期房"滞留乘客"交付监测（公益/信任资产）

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 第十二章三类被忽略者之 1：存量期房已签约购房者——新制度保护增量，存量项目交付风险不变甚至恶化；37 条新老划断缓冲带；v5.4 结语：三类代价长期无制度回应，侵蚀改革合法性 |
| ② 需求 | 已签约期房业主的交付焦虑：看不见项目进度与资金状态；这是"账单背面的三类人"之一，也是平台的信任试金石 |
| ③ 智见机会 | 公开信息整理的交付进度监测（施工进展公开信息、政策动态、保交楼白名单动态）——**只做信息整理、不做结论、不引发恐慌性维权（风控红线）**；公益性质，服务"被制度遗忘的存量" |
| ④ 贝壳生态杠杆 | 平台社会责任 + 信任资产（服务业的核心是信任）；小区页载体 + 经纪人属地服务网络（ACN 的社区触角） |
| ⑤ 变现形态 | **无收入预期，纯公益/口碑**；为远期 Agent 沉淀信任与数据入口；潜在舆情对冲价值（监管与地方的间接认可） |
| ⑥ 验证锚与时间窗 | 舆情与投诉数据（改革合法性侵蚀指标）；若政府推动存量项目信息披露，此卡从公益转半公益服务；做难而正确的事——不以 ROI 立项 |

### 机会卡 C5（远期，不拔高）：个人不动产研究 Agent

| 要素 | 内容 |
|---|---|
| ① 新政触点 | 选择风险制度化（购房者=延期付费者）——远期需求的制度底座；红线、置换、交付风险三件套让"可验证研究过程"有了具体内容 |
| ② 需求 | 城市—板块—房源三层 + 家庭现金流（收入/首付/月供/持有周期，用户输入口径）的可验证研究过程——结论有条件、假设可调整、历史可复现（客户六源稿定位） |
| ③ 智见机会 | 客户六远期定位不变：C1-C3 工具沉淀的数据入口与口碑之上，远期 Agent 才有落地基础——**先慢后快，不抢跑**；Agent 四件套（专家 skill + harness + 垂类模型 + 专用终端）复用 A 智囊层规划 |
| ④ 贝壳生态杠杆 | T 终端层（CLI/客户端/API）+ A 智囊层（Agent 四件套）+ 轻量指标查询入口（现阶段） |
| ⑤ 变现形态 | 远期，不做收入指标；可能的家庭订阅需先验证工具期转化与留存——**不设预期，不编收费模型** |
| ⑥ 验证锚与时间窗 | C1-C3 的使用率与留存；工具期 1-2 年后评估；期房占比下降斜率（45-55%）验证"选择风险"焦虑的持续性 |

**C 端诚实评估**：四张现期卡全部是引流/生态内嵌/信任资产，唯一可收费方向在银行侧（合规获客数据，合规边界须清晰）。C 端战略价值 = 数据入口 + 口碑 + 信任，为远期 Agent 铺路——**信任换转化，不抢跑、不编收入**。

## 三、优先级矩阵与路线图建议

| 优先级 | 机会卡 | 付费方 | 杠杆 | 说明 |
|---|---|---|---|---|
| 高 | D1 并购前筛 | 整合者（银行/AMC/央企） | 客户三逻辑延伸 | 制度窗口最清晰（尽调成本骤降），借道金融机构年费 |
| 高 | C2 置换沙盘 | 平台整体交易量（无直接收费） | 贝壳核心场景+ACN | 与带押过户落地同节奏，服务费转型的抓手 |
| 高 | D2 土储处置 | 收储方（客户四） | 主 A 工作台扩展 | 随收储放量放大，不单独启动 |
| 中 | D3 好房子品质定价 | 银行/标准方 | I 标尺层+中房协 | 等 2027 年认证细则，先备数据能力 |
| 中 | C1 红线测算 | 银行（合规获客） | 计算器入口+经纪人 | 工具先行、银行付费在后 |
| 中 | C3 交付风险提示 | 无（信任资产） | 房源页+真房源 | 现房分销的转化入口 |
| 低 | D4 投后复盘订阅 | 开发商（缩表） | CLI/API 标准化 | S 层扩展，两灯塔后铺开 |
| 低/公益 | C4 滞留乘客监测 | 无 | 社区触角+ACN | 信任资产，不以 ROI 立项 |
| 远期 | C5 个人研究 Agent | 待验证 | A 智囊层 | 1-2 年后评估，不抢跑 |

**对总路线图的四条建议**：
1. **开发商线借道不直收**：D1-D3 全部挂靠客户三/四的合同与复购（两灯塔），开发商侧不设收入目标——规则比规模更重要，先立"围绕交易的数据服务"的规则，再谈规模。
2. **C 端线以"三件套"替代"远期 Agent"叙事**：红线测算、置换沙盘、交付提示是政策直接开票的三个 C 端需求，比远期 Agent 更能在 12 个月内落地；远期 Agent 是它们的收敛形态。
3. **服务者权益不缺席**：C 端工具必须同步给经纪人用（测算器、置换沙盘进工作台），中小代理是第十二章被忽略者之二——工具赋能不能只做 C 端、把经纪人留在旧模式里等出清。
4. **风险提示的边界纪律**：C3 只做"提示"不做"评级"，防止平台从信息提供者变成风险裁判——责任一旦上身，信任资产就变成责任负债。
