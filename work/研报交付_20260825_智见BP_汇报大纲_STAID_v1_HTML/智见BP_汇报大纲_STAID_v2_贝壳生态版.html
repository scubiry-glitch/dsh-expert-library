SEC.1

客户与解决方案

Q1 CUSTOMERS & SOLUTIONS

六类客户，每类按四个维度展开：需求痛点 ｜ 行业最佳实践 ｜ 我们的解题思路 ｜ 预计数据源。

1.1 六类客户分述SIX CUSTOMER SEGMENTS × FOUR DIMENSIONS
①

中央部委

住建部、央行、金融监管总局、发改委等
需求痛点
  • 全国层面市场监测依赖地方报送，口径不一、更新滞后
  • 政策效果缺乏可核验底稿
  • 跨部门数据分散，「看不见决策过程」
行业最佳实践
  • 统计局 70 城房价指数（只给同环比）
  • 央行城镇储户问卷；住建网签系统；REITs 信息披露制度
我们的解题思路
  • 政府市场监测与领导直问入口（免费，换标准与共识）
  • 统一口径指数；政策效果复现（给定历史时点重放数据、假设与计算）限定为「已发生事实 + 透明假设」的同条件重放：不做反事实承诺、不替代政策评估结论（研判建议 5）。
  • 只描述已发生、不做趋势承诺
预计数据源
自爬住建网签备案自爬统计年鉴与 70 城自爬自然资源部土地市场网自爬+合作政策文本库
②

地方监管

省住建厅 / 市住建局、房管局、地方金融监管
需求痛点
  • 区县口径对齐难；小区级价格缺失
  • 舆情与价格监测手段弱
  • 40 城 vs 50 城口径差异要向领导解释清楚分层处理：40 城做深（价格 + 活跃 + 成交全口径）、50 城做广（价格覆盖），口径专项说明本身作为可交付产品并列入灯塔交付物（研判建议 3）。
行业最佳实践
  • 成都样板：区县对齐、极端值裁尾、小区价格、迁移指数
  • 统计局 70 城只给同环比的做法
我们的解题思路
  • 地方版监测：地图 → 城市 → 区县 → 小区价格、迁移指数
  • 市场监测大屏（白标）；领导直问（白名单 300 人）
  • 过舆情审核后再对外
预计数据源
自爬地方网签/备案自有挂牌与成交合作迁移指数自爬土地自爬+合作政策库
③

金融机构

银行、保险、券商
需求痛点
  • 抵押物估值依赖单点评估报告，贷后无持续监测
  • 压力测试缺数据与统一口径；不动产风险敞口难量化
  • 评估报告不可复现、签章责任重
行业最佳实践
  • 巴塞尔 IRB 内评体系；银行押品管理（双人复核、定期重估）
  • REITs 估值 CapRate 法；DSCR 压力测试（监管压力情景）
我们的解题思路
  • 主产品 B 金融机构不动产风险工作台：T0 估值 + T+N 监测/预警
  • 抵押物估值参考、价值偏离预警、持续可查的价值台账
  • 估值只做过程不做结论（做底稿、不做签章）让出的银行押品法定评估刚性付费点，以评估机构协作分润补位：§4.3 合作项已有方法论协作，明确分润机制即可（研判建议 10）。
预计数据源
合作输入押品与信贷台账自爬土地供给合作输入消费信贷表现自有+自爬公开成交/挂牌自有+采购租金
④

保租房国企

城投 · 住房运营平台
需求痛点
  • 收储决策不可复现（一项目一评估）
  • 缺四本账：事实 / 假设 / 方法 / 责任
  • DSCR 与租金定价测算口径不一
  • 「项目可以不赚钱，过程不能说不清」
行业最佳实践
  • 保障房 REITs 信息披露与审计要求；评估机构双签
  • 政府收储政策工具箱：收购折扣、财政补贴、贴息贷款
我们的解题思路
  • 主产品 A 国企收储决策工作台：收储测算包
  • 收购折扣 × CAPEX × 保租租金 × 出租率 → NOI → DSCR 基准/压力双情景双情景对标监管压力情景（参考 DSCR 监管压力测试惯例）；保租租金与出租率假设是收储测算最大变量（研判建议 7）。
  • 四本账 + 审批链 + 复现链、证据逐级下钻
预计数据源
自有挂牌/成交/租金客户提供项目级租约与现金流自爬+合作政策库自爬土地
⑤

开发商

投资 · 销售 · 库存
需求痛点
  • 城市进入与拿地决策依赖经验和外部报告
  • 项目定价与去化预测缺可复核依据
  • 投后复盘无底稿
行业最佳实践
  • 头部房企城市地图与客研体系
  • 中指 / 克而瑞榜单与数据库
我们的解题思路
  • 城市监测订阅：标准组件交付（CLI 查询、客户端、API）
  • 开盘定价支持（条件化解释、不承诺结果）
  • 土地供给与去化周期分析
预计数据源
自爬土地市场自爬网签自有成交与带看

1.2 商业模式落点BUSINESS MODEL
政府端 · 免费入口

部委 / 监管

免费入口，三样非现金回报：标准、共识、数据入口。

生态研判增补 · 上限

政府端免费投入设上限（≤ 总成本 20%，银行视角建议值），以「部委 / 协会采纳智见口径」为继续投入里程碑；标准采纳是慢变量（政策周期约 18-24 个月），免费投入 ROI 不能悬空（研判建议 6）。

B 端年费三包

机构基础包 → 业务解决方案包 → 扩展包

机构基础包 · 数据 + 模型服务 业务解决方案包 · 工作台定制 + 私有化部署 扩展包 · Token 额度 / 大屏 / API / 嵌入式组件
定价纪律

先立纪律、再谈数字

银行千万级合同为目标假设（需验证），不写进对外承诺。

收入以数据服务、模型服务、工作台与风险运营服务为主，不把会员卡、返佣等混入智见。
生态研判增补 · 付费测试

灯塔期内以需求访谈 / 意向书获取 2-3 家银行预算参考区间与 10-100 万级试点付费意向，反推机构基础包价格带；把「可审计」翻译为减值计提、押品充足率、检查整改成本等银行 KPI 语言（研判建议 2）。

差异化结论 · DIFFERENTIATION

竞品卖数据 / 报告 / 榜单 / 单点评估，我们卖可审计的决策过程。

  • 四本账（事实 / 假设 / 方法 / 责任）+ 五条横向链（身份 / 版本 / 证据 / 审批 / 复现）+ 同条件重放
  • 竞品最难跟上的工程量：假设版本、审批快照、同条件复现 —— 这三项是客户愿意付年费的部分
  • 边界声明：不与评估公司抢签章、不与数据商比条数；评估机构方法论可作协作对象
  • 生态研判修正：让出的银行押品法定评估刚性付费点，以评估机构协作分润补位（§4.3 合作项明确分润机制，研判建议 10）
  • 数据供应商（久谦等）是上游采购渠道而非竞品，划清「买数据 vs 卖决策」的定位

SEC.3

T·A·I 三层规划

Q3 TERMINAL · AGENT · INDEX

T 终端层解决「客户在哪里使用」，A 智囊层解决「如何理解事实、政策和指标」，I 标尺层解决「用什么指标和方法判断」。

T

终端层

标准组件 + 定制化交付 —— 决策动作发生的地方
Terminal

标准组件（开箱即用）STANDARD

  • CLI：命令行查询、批处理、报表脚本、自动化运维（供数据团队 / ISV 集成）
  • 大屏：政府市场监测大屏、银行风控监测大屏（可白标）
  • 客户端：网页工作台（估值工作台、监测预警台、审批台）、桌面端
  • API 与嵌入式组件：指标接口、报告接口、嵌入式仪表盘、消息推送

定制化交付（按客户决策流程定制）CUSTOM

  • 私有化部署：整套终端下沉客户环境，数据不出域
  • 白标：客户品牌与配色（贝壳蓝 / 银行蓝等）
  • 系统集成：与 OA、信贷审批流、评估系统、数据仓库对接
  • 专属终端：按客户决策流程定制「录入假设 → 发起审批 → 查验 → 复现」闭环
原则终端不只是「看数据」的地方，而是决策动作发生的地方。
A

智囊层

两类 Agent：私有化与预置专家 / 一体化专业 Agent
Agent

Agent A · 私有化与预置专家（数据敏感场景）

  • 私有化部署：模型 + 知识框架 + 工具链整体下沉客户环境（银行、国企等数据敏感场景，满足合规要求）
  • 预置专家：专家知识框架预装（33+ 位专家、五域分类、BK 档案），不依赖外部模型调用、离线可用

Agent B · 一体化专业 Agent（效率-成本-质量三重最优）

  • 专家 skill：解读框架 / 路由 / 输出规范 / 技能包
  • 专用 agent harness：任务编排、工具调用、证据链回写、多步推演
  • 垂类模型：不动产语料微调 ＋ 专用终端：对话 + 底稿 + 审批一体
对比「通用大模型 + 通用终端」：效率更高（一次成稿、少返工）、成本更低（Token 用量少、缓存复用）、结果更好（口径统一、带证据、可审计可复现）。

只做四件事（沿用 v37 纪律）

  • 解释
  • 检索
  • 条件推演
  • 组织证据

明确不做三件事

  • 不做趋势承诺
  • 不替客户决策
  • 不隐藏不确定性
专家引擎原则卖稳定的观点结构、不卖某个人的名字；输出必带引用与假设条件。内置多专家分歧管理机制，输出显性呈现观点分歧与置信边界，防知识框架僵化成新黑箱（研判建议 8）。
I

标尺层

标准化指标体系 + 开源估值框架
Index
标准化指标体系INDEX SYSTEM
价格指数基期 2020-01

呈现只给同环比，参照统计局 70 城做法。

活跃指数基期 2024-01

子指数共 7 项；覆盖口径 40 城 vs 50 城分层：40 城做深（价格 + 活跃 + 成交全口径）、50 城做广（价格覆盖），口径专项说明作为可交付产品并列入灯塔交付物（研判建议 3）。

信心指数暂无基期 · 暂缓对外

每指数强制附带释义：100 以上意味着什么、以下意味着什么。补重启条件：覆盖 X 城 × Y 个月后重启（口径待定），列入灯塔交付物（研判建议 4）。

开源估值框架（两套公开锚 + 一套现金流模型）VALUATION FRAMEWORK
ANCHOR 01中房协「好房子」标准

安全耐久、健康舒适、绿色低碳、智慧便捷等品质维度 → 品质溢价与价值锚。

ANCHOR 02不动产 CAPM

Rf + β×ERP + 流动性溢价 + 政策风险溢价 → 折现率 / 资本化率锚定。

贝壳生态研判结论

四专家评审 · 框架 B ECOSYSTEM REVIEW

四位贝壳生态专家（杨现领 bk-033 渠道/存量流通 · 左晖 e08-08 平台经济 · 柴强 bk-018 存量统筹 · 琉 bank-11 银行战略咨询）以框架 B 四段式对 STAID v1 大纲独立研判：定位成立、商业模式方向正确但节奏错配、壁垒在工程不在数据条数、落地须聚焦。本附录为正式稿（底稿 t5 融合结论）；正文相关处已按 10 条增补 / 修正建议标注「生态研判」批注。

A.1 核心结论（摘要）FIVE KEY TAKEAWAYS
1

定位成立

STAID 五层把不动产数据生意从「卖数据」改写为「卖可审计的决策过程」，恰逢存量流通时代（收储、保租房、REITs、二手置换）的决策审计刚需：项目可以不赚钱，过程不能说不清。四视角一致认可架构自洽与边界纪律（做过程不做结论、做底稿不做签章、只给同环比、信心指数暂缓对外）。

2

方向正确、节奏错配

政府免费入口换「标准 / 共识 / 数据入口」成立，本质是先占入口再收年费；但标准采纳是慢变量（政策周期约 18-24 个月），与「60 天两灯塔」快节奏错配，免费投入须设上限与可核验里程碑。

3

壁垒在工程不在条数

四本账 + 五链 + 同条件重放是中指 / 克而瑞 / Wind 短期难跟的重工程；贝壳研究院应从竞品表移入生态协同：其方法论与 BK 专家体系（33+ 位、五域分类）恰是智见 A 智囊层现成资产。

4

落地须聚焦

60 天双灯塔资源必然稀释，应二选一打透（收储全流程冲刺，或单点打透银行主 B）；BP 须补 Ask：从叙事文档改为决策者可直接批 / 不批的决策文档（预算、负责人、时间表、止损线）。

5

关键待验证

银行「千万级合同」是目标假设，须以 2-3 家银行预算参考区间与 10-100 万级试点付费意向实证；第一步成败以续约、复现使用与「口径被政府采纳」为证，而非签约数。
