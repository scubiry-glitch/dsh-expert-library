# 交易专家 · toB 商业模式专项分析（修订版）

> 基于 2026-09-14「交易专家项目商业化对齐」会议纪要 + 《商业银行个人居住房地产估值与监测服务》推广材料（容诚企业咨询，2026.08）。
> **口径**：B 端 = toB 业务，含两条产品线——① **toB 评估与咨询服务**；② **toB 营销服务**。C 端 = 面向消费者的专家服务（按次/会员/成交分成），仅作辅助验证。

---

## 一、模式一句话

**围绕银行做两类 toB 生意**：
1. **评估与咨询服务**——给银行的房产押品贷款加一条"可交叉验证、可持续复核的市场证据线"（估值参考、监测、咨询分析）；
2. **营销服务**——把贝壳交易流量中的高意向商机开放给金融机构（理财引流/商机分发），叠加 CPT 包段服务与 Agent 开放平台接入。

贝壳/平台不碰金融牌照业务，卖的是**数据证据、流量和管道**。

## 二、toB 两条产品线

### 产品线 ①：toB 评估与咨询服务（对标推广材料）

**定位**：不是替代银行既有评估与审批，而是补充一条高效、透明、可复核的市场证据线；明确"不构成资产评估报告或房地产估价报告"，规避牌照与责任问题。

**四类银行场景 × 三层市场证据 × 一条可追溯链**：

| 场景 | 服务内容 |
|---|---|
| 贷前准入 | 单套市场价值参考：可比成交与样本边界 |
| 存量监测 | 批量更新与 LTV/覆盖异常触发复核清单 |
| 区域预警 | 城市—板块—小区量价与流动性分层 |
| 不良处置 | 处置时点与折价空间、租售流动性参考 |

**痛点对位**（材料 P2）：时点评估撑不起高频批量复核、数据口径不透明、区域分化难传导到单套、价格差难定量归因 → 对应"持续估值+异常触发 / 证据链可追溯 / 四层联动 / 定量归因"。监管背景：70 城二手住宅较高点累计回调 23.18%、六大行住房贷不良率 0.67%→0.88%、经营类 1.58%→1.92%，高评高贷与押品估值是处罚关注点。

**交付形态**：咨询报告（单套测算/批量复核/区域监测/不良处置咨询）+ API 服务（结构化区间、证据与版本，接入授信/押品/不良流程）+ 银行场景 Agent（组织案件→匹配证据→留版本→识别异常→人工复核）。

#### 平台能力底座：智见专家 Agent 开放能力

评估咨询线的生产能力由**智见专家 Agent 平台**支撑，合作伙伴开放能力开发文档（[partner-devdoc](https://yy.meizu.life/render/zhijian/partner-devdoc.html#s1)）定义了完整的生产体系：

- **专家 Profile（schemaVersion 2）**：把专业方法论变成可被点名的专家——persona + 方法 + 约束 + 输出规范 + 评分量规（rubrics），建队时烘焙成成员，评分反馈闭环让专家越用越准；
- **任务 DAG（Scenario）**：如"估价报告复核"场景——要件核验 → 比较法复核 / 收益法复核并行 → 融合复核意见书，梳理先行、多视角并行、融合收口、渲染验收；
- **输出模板 + 质量门禁**：五道起步门禁（禁例 token 0 命中、数字逐 token 一致、渲染 0 溢出、排版审计、大纲对照），硬门未过的交付物到不了客户手里；
- **数据源通道**：Wind / 政研通 zyt / 贝壳三通道统一调用面（`expert_provider_call`），返回信封强制携带口径（caliber）与单位（unit），"编数字比不回答更严重"的四级数据标注纪律。

#### 容诚最佳实践：单套租金测算咨询报告（v2）

**案例**：《佳馨苑 1 座 506 单元 · 单套住宅租金测算咨询报告》（容诚企业咨询，2026-07-01，报告编号 RCE-FZ-JXY-2026-0701-001，委托方为政府平台公司福州安住发展）。这是评估咨询线"单套资产"颗粒度的**交付标杆**，其方法论骨架可直接复刻为产品模板：

| 方法论环节 | 报告中的落地 |
|---|---|
| 报告性质前置声明 | 开篇"报告性质提示"：不构成资产评估/估价报告，不替代法定程序——与推广材料免责口径一致 |
| 模型测算 + 样本校验双轨 | 模型参考点 2,364 元/月（25.64 元/㎡·月），再以同小区 5 套可比样本修正校验（加权 2,203 元/月），差异 6.8%–16% 如实披露"不宜表述为强支撑" |
| 可比样本逐项差异调整 | 面积/客厅数/卫生间数/出租时间逐项量化影响（如 R-04 面积差 -1,031 元/月），调整矩阵全披露 |
| 样本深度分级使用 | 同小区近 12 个月仅 5 条样本 → 明示"样本支撑偏弱，建议区间不宜过窄"；宽口径样本（150/206㎡）只作校验不作依据 |
| 事后检验 | 另用 2026-06 的 880 条样本回测，平均误差 13.9%——模型可信度可量化 |
| 区间形成逻辑 | 不取单一测算值或单样本，建议参考点 2,300 元/月、区间 2,000–2,600 元/月，并给出"区间中上部/中下部"的使用条件 |
| 衔接与交叉验证 | 与同标的交易价格测算报告衔接（建议价 94.8–109.3 万 → 静态租金收益率 2.69%） |
| 全样本附录 | 8 条候选样本含 3 条未入选样本及落选原因——证据链对外的极致形态 |

**证据留存**：报告及底层数据的证据留存入口为 [dss.ke.com/valuation](https://dss.ke.com/valuation/index.html)——每个测算结论可回溯到样本与参数版本，这正是"可交叉验证、可持续复核的市场证据线"的交付承诺兑现实例。

**对产品化的含义**：这份报告证明评估线的核心资产不是"AI 写报告"，而是**"测算模型 + 样本调整矩阵 + 事后检验 + 证据留存"的完整证据链工艺**。银行买的正是这条链：每一个数字可追问、可复核、可追溯到版本。

**商业化落点**：这就是会议中"理财引流 + **风险评估**"2000 万级组合里的"风险评估"一侧——年费制咨询/API 服务，按场景模块或押品规模计价。

### 产品线 ②：toB 营销服务

#### 服务流程

```
贝壳 APP 交易流量（找房/关注/IM 咨询/金融工具使用）
        │
        ▼
① 画像沉淀 ──→ 用户画像库：资质、行为、资金意向标签
        │
        ▼
② 商机识别 ──→ 金融意向信号：购房资金规划 / 理财咨询 / 按揭意向
        │
        ▼
③ 分层分发 ──→ 分类器拆分群体，按机构承接能力与客群匹配度分发
        │          （CPA 结算：有效线索 = 预约完成/留资核验通过）
        ▼
④ CPT 包段服务 ──→ 机构包断专属时段/场域：专家坐席时段、
        │            板块/楼盘场景冠名、活动专场（按包段时长计费）
        ▼
⑤ Agent 开放平台 ──→ 机构插件化接入：自带产品/制度/理财接入专家场景
        │            （接入年费 + 通用 token 消耗按量计费）
        ▼
⑥ 机构自主转化 ──→ 银行在其自身商业模式中闭环（理财转化/按揭/高净值）
```

#### 核心产品分解

| # | 核心产品 | 内容 | 计费方式 |
|---|---|---|---|
| 1 | **商机分发** | 理财引流、按揭线索开放给机构；"圈出高意向人群 + 分类器分发"；有效线索定义合同锁死（预约完成/留资核验通过，空号/拒接/重复不计费） | **CPA**（按有效线索计费） |
| 2 | **CPT 包段服务** | 机构包断专属资源时段：专家坐席时段（如每周 N 小时专属金融专家）、板块/楼盘场景冠名、专场活动（如宁波银行理财专场周） | **CPT**（按包段时长/场次计费，时段内资源独占） |
| 3 | **Agent 开放平台接入** | 插件化接入、计费系统、数据围栏、频率限制；机构自带产品"插进来"自主运营 | **年费分层**（基础/专业/旗舰） |
| 4 | **通用 token 消耗** | 机构调用 Agent 能力产生的模型消耗，按实际用量结算 | **按量计费**（市场化 transparent 定价，无差价结构） |
| 5 | **数据和模型服务** | **数据**：贝壳政研通 CLI——政策、指标、行情等房地产领域权威数据接口，口径与单位强制溯源；**模型**：参照成都数据集团数据基础设施能力体系（国家数据基础设施成都节点、可信数据空间、隐私保护计算，见《四川区域功能节点和成都数据基础设施服务能力介绍》），构建区域、人群、客群等多类画像模型，支撑机构客群洞察与风险识别 | **订阅 + 调用**：数据接口按订阅/调用量计费，画像模型按场景订阅 |

> 口径说明：不含 CPC（按点击）与 CPS（按成交分成）——转化环节完全归机构自主运营，平台只对"交付给机构的确定性资源"（有效线索、包段时段、接入能力、消耗用量）收费，权责边界清晰。

**银行收益闭环**（决定其为什么付费）：高净值客群获取、理财转化、按揭转化——每家银行的闭环点不同，接入前必须先对齐其商业模式（会中原话："他最终拿到的是什么？一定要回归他自己的商业模式"）。

## 三、层级结构

| 层 | 主体 | 提供什么 | 得到什么 |
|---|---|---|---|
| 证据/服务层 | 评估咨询服务 | 估值参考、监测、归因、Agent | 年费/项目费（2000 万级组合的一部分） |
| 流量/平台层 | 贝壳 Agent 开放平台 | 商机、画像、插件化接入 | 服务费、分发计费、包段计费 |
| 机构层 | 银行/保险/券商 | 金融产品、风控、转化运营 | 客群与转化，闭环自身商业模式 |
| （辅助）C 端 | 交易专家服务 | 按次咨询/会员陪伴/成交分成 | 验证服务价值与定价，非主收入 |

## 四、为什么是这个模式（而非自营）

- 自营财务陷阱（美租/自如教训）：收入分期确认、成本一次确认 → 做得越大亏越多；且组织人力紧张，扛不住重履约。
- toB 两线均为轻资产：证据线靠数据+模型，营销线靠流量+管道；**跑通一家银行后可复刻**。
- 合规姿态干净：评估线明确"不构成评估报告"；营销线把履约与转化责任交给持牌机构。

## 五、核心风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 金融合规 | TOC 直连有主体责任；评估线不能越界成"评估报告" | 先理财后按揭；材料已加免责声明与"另行履行程序"条款；合规问题转人工 |
| 数据安全 | 开放接口穿透、超范围调用 | 每机构数据权限白名单、并发/频率限制、仪表盘监控 |
| 边界冲突 | 与北京试点专家项目、OSA/云管家链路纠缠 | 两项目刻意保持边界；与原项目经理（张强）对齐接口 |
| B 端使用能力 | 银行"能不能接、会不会用明白" | 自助化装修（类淘宝店铺）+ benchmark 工具；先 1-2 家标杆再复刻 |
| 商业闭环 | 银行付费理由必须落到其自身模式 | 接入前逐家定义闭环点（理财/按揭/高净值） |

## 六、推进节奏（会议共识）

1. **2 周小验证**（十一后启动）：内部先定清 C 端定价 SKU + toB 两线的打包方案。
2. **标杆客户**：宁波银行北京分行（次日 9 点拜访，总行零售信贷部负责人 + 北分零售一把手出席）——评估线与营销线可同场推介。
3. **区域扩展**：北京验证 → 上海/苏州（江苏银行等线索）。
4. **品类节奏**：银行先行（理财切入），保险/券商后置，不双线齐铺。
5. **组织**：立项主体问关恒；3-5 页能力全景+商业化框架材料近期出。

## 七、待回答的开放问题

1. 2000 万级组合中，评估咨询服务与营销服务（引流/分发）各占多少？
2. 评估线的计价基准：按押品规模、场景模块数还是年费？与行内既有评估供应商（如科瑞瑞类，材料外推）如何比价？
3. 银行对接部门：授信/押品/风险（评估线买家）vs 零售/私行（营销线买家）——是否需要两套话术两拨人？
4. 商机分发的转化数据回写口径：虽按 CPA 结算，但转化回流数据是优化分发模型与 CPT 包段定价的基础，机构是否开放？
5. CPT 包段服务的资源边界怎么定：专家坐席时段如何与 C 端自营服务排期隔离？包段内的服务承诺（响应时长、专家等级）如何写入 SLA？
6. 通用 token 消耗的对客计价：按官网价直传还是平台统一价？机构用量超预期时的限流策略？
7. C 端 AI 评测通过标准与放开时间表？
