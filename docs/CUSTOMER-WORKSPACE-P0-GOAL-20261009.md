# 客户工作区第一阶段目标（P0）

**日期：**2026-10-09  
**范围：**客户 `/app` 的会话、工作区与数据视图；独立审核页继续可用。  
**目标：**客户进入任一会话后，能立即知道研究到了哪一步、自己要处理什么、团队正在做什么，以及正式报告在哪里。

## 完成定义

1. 工作区抬头和四阶段从服务端 `presentation.stages/labels` 取状态；已交付会话显示报告主入口，未交付会话显示真实下一步。
2. 当前会话的 `customer_ask_question`、计划确认、大纲和正文选择都出现在跨视图“待我处理”区。每项只保留一套提交控件；计划仍使用 digest/revision，稿件仍使用 SHA，提问仍使用 requestId。
3. 新增用户输入可在确认计划前复核；输入变化时确认按钮不可用。用户可请求队长修订，或显式确认原计划仍适用并生成待审新版。
4. 团队任务默认可扫读；完整描述和技术原文按需展开。保留真实专家人物、依赖路线和手机列表视图。
5. 同一正式结果只有一个主卡，优先阅读 PDF；其他格式和过程档案收进次级区域，正式文件不重复出现。
6. 账号归属、私有预览和下载、报告质量门、会话消息与数据能力维持原有服务端边界。无变化的工作区响应不重建页面。

## 当前实施

- 客户页：`apps/customer-portal/public/index.html`、`app.js`、`style.css`。人物使用现有专家图，动作只与真实状态相连；任务路线使用依赖数据绘线。
- 人物路线按独立审核页的视觉规则对齐：步骤标尺、状态图例、244px 专家书桌卡、纸张与手势、依赖接力线、任务聚焦，以及长路线的缩放、全图和逐项定位。手机仍默认显示任务列表。
- 服务端：`src/index.ts` 在当前账号会话的工作区投影中提供只读输入变化摘要；`src/host/customer-gateway.ts` 以版本和上下文 SHA 校验生成新版动作；客户 BFF 保留账号会话归属与 CSRF 检查。
- 资源：客户页构建和静态路由支持现有专家全身图，原头像路径继续可用。
