## 如何配置子代理模型

在设置中的专家库管理进入「模型设置」，填写默认模型和具体专家的 provider/model，可选推理强度。

预置 DAG 按「专家模型设置覆盖 → 专家预设 → 插件默认 → 队长模型」解析。AI 编排的 profile 若显式指定成员路由，则采用成员指定；其次采用 profile 默认路由，再落到专家设置等继承链。用户最新明确要求当前 real 租户统一使用 Kimi K2.8 Preview，实时目录路由为 `kimi-coding/kimi-for-coding`。本轮重跑已据此替换此前 GLM 控制指令，原始业务需求保持不变。

real 的队长默认已是 Kimi；已在专家库设置中写入 Kimi 默认和当前 208 个专家的同模型覆盖。原生 spawn/fork 及 preset 的历史默认也已改为 Kimi，已完成重载。scoped preset 工具此前没有读取 Host settings，现已修复并完成 100 项相关测试和 5 个实际隔离 Host 验证；不能以设置页面正确代替真实成员请求证据。

这些是默认与专家预设覆盖，不会修改历史会话，也不会重写已经冻结的计划。明确指定的 profile/member 路由仍有更高优先级；本次重跑输入要求所有成员和审核员都显式使用 Kimi，将核对实际计划及请求。推理强度省略以使用模型默认，不能沿用旧模型的 `max`。

生成计划时确定模型、推理强度和来源，连同计划一起形成版本摘要。确认后按同一份快照创建子代理，不在启动阶段重新读取设置并悄悄替换。设置变更影响新生成或重新编辑的计划；现有待审计划、运行中成员和历史记录保持原值。已冻结模型不可用时，应在创建团队之前报告原因，修改或重新生成计划后再确认。

「研究计划与执行」展示 DAG、前置依赖、成员模型及来源、验收条件和已选领域工艺。UI 的「计划已应用」只表示团队配置已执行，不代表报告通过质量验收。

## 为什么之前没看到研究计划确认

R11 的会话证据显示：AI 暂存计划后约 12 秒自行调用批准，期间没有新的用户确认；界面默认折叠且应用后不再保留待审卡。原实现没有强制区分用户确认和模型自述确认，因此不是用户漏看了一个可靠的确认环节。

候选现在默认等待用户确认：计划持久保存，卡片展开，点击「确认并开始执行」由认证 Host 用户批准具体计划版本。等待时暂停本插件持有的 Goal 并结束当前回合，避免不断自动续跑；批准后仅恢复仍匹配的暂停版本，用户自己暂停或修改过的 Goal 不被覆盖。模型提交 `user_approved=true` 或声称已经确认不能获得用户权限。

已明确授权的自动重跑采用独立的 Host 授权记录：固定会话、直接用户输入摘要和单份计划，记录请求号、原因、有效期及实际消费的计划版本。单独出现 `/goal` 或「目标模式」不等于已经授权任意计划。此次自动实跑的授权依据是用户之前明确要求新会话重跑并持续观察优化，不是模型自行推断。

## 领域工艺边界

智见研报工艺由 `zhijian-realestate` 管理，一个包可有多个 skill。AI 发现并显式选择所需组合，提供选择理由；Host 负责版本冻结、角色材料交付和证据管理，不代替 AI 根据关键词选定 skill。旧版预置研报入口也必须声明最终报告任务并提交同样的 v3 工艺选择，不能成为绕过路径。

机器检查覆盖所声明的结构、数量关系、政策证据要素、视觉与制品绑定；独立内容审核仍需核对官方原文、适用范围和业务推理。完整参考材料交付及全部适用门禁有证据，不能等价宣传为 AI 永远不会出错。
