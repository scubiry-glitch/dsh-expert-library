# 独立页会话阅读优化 · 2026-10-08

目标：在保持发送、授权和实时通信行为的前提下，完成移动端会话的五项阅读与导航优化。

- 在底部隐藏“最新”；离开底部后显示入口。新消息按序号去重计数，不打断历史阅读，回到底部清零。点击入口在已加载记录中定位，不重置历史分页。
- 根据 VisualViewport 的高度和偏移重新计算消息区域，响应键盘引起的 resize/scroll、输入框聚焦与失焦；输入框高度限制为 42–140 px。
- 提问记录支持不区分大小写的关键词筛选、无结果提示，并在关闭重开时保留搜索词与列表滚动位置。搜索范围明确为已加载记录，更早记录继续使用原分页读取。
- 相邻同角色且相隔不足五分钟的消息弱化重复头像和姓名；跨日或间隔五分钟以上分段显示时间，保留原始消息顺序。
- 长回复显示最多五行原文摘录，不生成新结论。改善正文段落、标题、列表间距，展开时保持摘要位置，末尾提供收起入口并定位回摘要。

## 验证与生效

`node scripts/qa/review-conversation-experience.mjs` 使用完全拦截请求的浏览器样例，验证新消息计数/去重与历史位置、搜索/空结果/列表位置、时间分组、长文展开收起、模拟键盘可视区域变化及 320/390/768/1440 像素宽度。内部辅助函数仅在拦截的测试脚本响应中暴露。

`node scripts/qa/review-client-stream.mjs` 为本地隔离 HTTP/SSE 回归，不发送真实消息。“最新”现在只滚动，因此并发读取测试改为通过测试响应内的辅助入口发起读取，保留 HTTP/SSE 合并检查。

两项浏览器验证均通过，页面错误为零；通信回归补齐了 75 条离线消息，17 秒空闲观察期间无状态或对话轮询。结果见 `evidence/review-experience-20261008/verification.json`。

线上 HTML、JS、CSS 逐字校验见 `evidence/review-experience-20261008/live.json`。静态资源由在线路由按请求读取，资源内容 hash 更新缓存版本，不需要为这次 UI 修改重启服务。

发布前备份：`/root/zhijian/deploy-backups/review-experience-20261008/`。截图位于同一 evidence 目录。

限制：键盘测试为浏览器可视区域模拟，未在真实飞书 Android/iOS 键盘上测试。搜索和位置记忆保留于当前页面，不把对话内容写入浏览器持久存储。
