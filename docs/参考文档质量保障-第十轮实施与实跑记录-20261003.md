## 实现的保证

1. 两份参考源以固定身份维护。必读规范、组件、完整示例及历史业务内容有不同用途；渲染副本由构建生成并校验。缺失、歧义、哈希漂移和超预算均报错，不静默删减。完整参考 HTML 的路径可用于深读，不伪称未注入的全文已读。
2. Host 在任务交付、领取及审核准备时，按角色送入必读正文并保存与任务、attempt、会话和材料版本绑定的证据；每个模型续轮从持久任务记录恢复短的必读正文，覆盖普通续轮与冷恢复。并发上限仍为两名活动成员，原有成员工具边界不变。
3. 新工艺任务使用显式 v2 契约；老 v1 三件套契约保持兼容。最终 MD/HTML/PDF 增加内部证据台账，将真实章节、计算、HTML 定位与文件 SHA 绑定。
4. Host 可信执行路径检查来源披露、收束结构、PDF 结构、章节结构、受支持的计算、格式一致性和真实浏览器。审核员先领取当前材料与机器结果，再提交四个审阅领域的正文定位及理由。失败、未验证、过期和版本变化不得通过对应管理通道集成。
5. 修订继承原验收及剩余预算；不能用新建修订重新获得完整修复预算。精确重放保留原有证据，成品字节变更使旧检查失效。

“全部必需材料和适用检查有有效证据”是工程覆盖约束，不等于模型理解、所有数学公式和所有事实必然正确。计算器当前只认证已支持并绑定的公式类型；全篇语义仍需独立审核。浏览器保存实际 1280/375 首屏截图并检查适用 DOM，不将首屏截图称作全篇视觉审美认证。任意 shell 或外部发布权限不在插件管理放行的完全控制范围内。

材料逐项依据与成本边界见[材料实施小节](evidence/report-quality-round10-20261003/materials-implementation-note.md)。当前生产者必读包约 39 KB，审核包约 19 KB；这是 UTF-8 字节测量，不能直接换算成 token 或费用。首次分派和系统输入各含一份，后续系统请求继续携带规范；两份约 220 KB 的历史 HTML 全文没有每轮重复注入。最终成本以真实 usage 分项统计为准。

本轮查明的三类机制问题：

1. **修订交接缺口。** t2 第二次、t4 第二次分派先触发成员，具体审核失败项却直到后来的队长消息才出现；最初 assignment/status 只要求补发当前 attempt 的文件。因此，原样重发不能解释为“已收到具体修复意见仍忽略”。下一版从持久审核记录生成修订反馈，随同一次分派交付，并覆盖领取、状态读取及冷恢复。
2. **生产端自检范围不足。** 成文成员运行旧局部门禁及自写检查脚本，声称通过后，Host 全七项检查仍发现六项失败。新增官方本地预检直接运行与 Host 等价的完整检查；本地结果仍不能伪装成 Host 收据或独立审核。[自检过程证据](evidence/report-quality-round10-20261003/writer-preflight-observation.json)、[首轮 Host 检查](evidence/report-quality-round10-20261003/initial-host-machine-checks.json)。
3. **检查器有误报。** “结论与行动”是合法收束标题，却被基础检查拒绝、被章节清单误算为分析章；来源表的“政研通CLI（贝壳交付数据，dataView=internal）”被括号内供应商名称误归为两个通道；折行文字的字体测量框相交被当作字形遮挡，原截图中实际字形间有 7–18 像素空白。另一方面，HTML 把正文 h1 改成 h2、Markdown 的 12 个字面 `**` 与 HTML 不一致、PDF 页码等仍须按真实问题处理，不能把所有失败一律判成误报。[独立诊断与截图](evidence/report-quality-round10-20261003/final-audit/initial-check-diagnosis/diagnosis.json)。

这些发现说明：交付全部材料和建立门禁是必要条件，仍需实际验证反馈交接、自检入口和检查器自身的准确性。修复会保留真实负例、有限预算及旧收据的历史可读性，并禁止用旧检查器收据执行新版的放行动作。
