## 为什么没有验收通过

1. **通用引文定位缺陷。** 正文验证时删除所有下划线，而引文保留下划线，导致原文中的标识符被正确引用也遭拒绝。同构负例同时证明，删改后的不存在标识符反而可能通过。不能通过同时删除引文符号来修复，否则继续接受失真的引用。
2. **审核协议反馈不足。** 校验逐项遇错即停，隐藏后续错误；部分审核引用了 HTML 或 evidence JSON，而当前协议只接受固定 MD 锚。必须一次指出具体 area、引用索引、制品及允许的 MD 身份。业务 AI 将部分错误理解成 UUID 被改写，需要以真实校验定位纠正反馈机制。
3. **声明计算覆盖不全。** A1 台账只核验收益率情景，资金平衡遗漏自有资金，月租倍数公式和单位混用，另有过桥成本缺本金。这些没有被已有局部计算 PASS 覆盖。队长已经自主识别其中的资金平衡错误并尝试提交需修订结论，但正式审核被引文协议问题挡住，尚未产生有效修订轮次。
4. **现行政策核证不足。** A1 部分税率、面积档位有官方一手反证；CLI 的标题摘要不能证明现行规则。应把主张、官方原文、适用范围、生效时点和分析时点相连；原文未核得时保持未核验/条件分支，不能用模型常识补成现行事实。

独立内容审计、固定 SHA、逐项计算及官方依据见 [R11 A1 审计](evidence/report-quality-round11-20261003/r11-a1-independent-content-audit.md)。视觉仅抽查14页中的7页及一个表格细节，未发现明确遮挡或裁切；有一页内容稀少。它不代表完整视觉通过。

## R12 工作目标与边界

先对当前已部署 R11 代码及相关插件材料建立新的逐文件纯净备份，独立解包复验；业务文件、会话、诊断证据、缓存、凭据和无关领域包不入备份。只在独立候选中改动，通过后才提升和重载。

- **通用 Host：** 修复保真引文匹配；保留字内标识符和行内代码；隐藏文本/代码块不能冒充正文证据；完整返回多处定位错误。保持旧历史可读、精确重放及版本绑定。
- **领域包：** 在 `zhijian-realestate` 补资金平衡和租金倍数的有限类型计算、单位与正文覆盖检查；加强政策原文和时间适用性证据要求。通过正常样例及真实失败样例验证，不硬编码本报告的正确数字、地名或政策答案，不把领域规则塞进 Host。
- **流程核对：** 根据用户新提出的两点，核查预置 DAG 子代理模型配置的真实优先级与作用域，并查清研究计划确认阶段的实际入口、操作者及可见性。先区分计划入库、模型调用批准工具与用户确认，不把三者混称。
- **验证和实跑：** 完成有意义的失败/恢复测试及实际隔离 Host 验证，更新 real 已启用的本地域包，保持其他包和会话不变；在新 Session 用原业务重跑。独立审核应能提出问题、进入有限修订并最终验收，而无需观察者解卡。

继续遵守三个原则：工艺在领域包闭环；同包可有多个 skill；由 AI 选择适用工艺。100%仅指所选契约必需材料与适用有效证据覆盖及管理入口约束，不是模型任意事实永远正确的承诺。上述真实业务验收未完成前，不关闭总体 Goal。
