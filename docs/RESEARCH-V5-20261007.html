观点引领研究，工艺服务表达

继承“选专家＋推荐分析框架”；选择有价值的候选观点后重组大纲；由 designer-craft 把握神韵、逻辑与阅读节奏，HTML/PDF 执行两份参考文档的明确设定。

版本说明：本文是可审阅的 V5 实施方案，尚不代表 V5 运行模板已经上线。V3/V4、领域包旧版本和历史任务保留。V4 动态改写任务的发布物声明缺陷独立修复，不以修改旧冻结材料解锁。

一、V5 保留与改变什么

  • 保留：问题路由、专家选择、分析框架推荐、来源与口径纪律、独立评审、两份设计参考、不可变已审正文及可恢复执行。
  • 改变：用户优先选择值得检验的观点和研究方向；大纲随证据与表达需要重组。
  • 放宽：固定章数、标题逐字锁定、每章六件套、研究展开占比、固定增量数、固定图数不再是通用硬门。
  • 减少等待：专家简报、数据整理、编辑建议作为阶段内部工作；技术检查自动执行，集中返回问题。
  • 区分任务：研究、点评、策略建议采用不同方法组合。研究模式允许反证推翻主判断，停用“偏离主基调一律降级”的融合规则。

二、完整流程与用户决策

推荐专家＋分析框架 → 多专家提出候选观点 → 用户确认研究方向 → 重组大纲、并行取证、更新判断 → 成文＋表达设计 → 独立内容评审 → 用户确认正文 → HTML/PDF 制作＋独立交付验收

计划预览可先供用户调整专家和框架；启动后将实质研究决策集中在“方向确认”和“正文确认”。已有明确选择直接继承，只有发生实质变化才重新确认，避免多个界面重复审批同一件事。

决策点 A：选择值得研究的观点

展示推荐专家及替代组合、推荐框架及其适用边界，以及轻量证据扫描形成的候选观点。每个观点说明核心判断、解释机制、已有支撑、最强挑战、验证成本和读者价值。候选数量按题目需要，通常 2–3 个，不强制凑数。

用户选择的是优先检验的主线、范围、交付形式和预算。最终结论由证据决定；证据不足可以形成有依据的条件判断。结论被推翻不等于研究失败。

决策点 B：确认正文

用户看到的是观点清楚、证据与边界相称的可读正文，以及必要的表达示意。确认后冻结该版用于制作。未改变范围的标题优化、章节合并、证据补充无需逐次审批；改变课题、增加费用或对外发布才触发对应决策。

四、观点与大纲怎样协同

研究设计记录“问题 → 竞争解释 → 证据区分条件 → 暂定裁决 → 改判条件”。选中观点后，根据读者理解顺序组织章节；取证发现变化时，更新观点与大纲，保留修订理由。

智见报告工艺作为组织参考：总论明确问题与判断；分析章各自完成一个论证任务；事实、推导与边界清楚；结尾回扣主问题。角色对照、风险、情景、行动安排在确实需要的位置，可跨章合并，不要求每章重复。

需保留的深度V5 表达方式
假设及其脆弱处贴着相关判断交代前提、证据强度和失效条件，不强制“引假设”大节
机制与推导展示关键中间步骤；有量化基础才计算，相关性和因果分清
未来预演预测/策略课题按需设情景；事实复核可以给观察条件，不强写三年时间线
外部增量以是否解决关键问题判断价值；数量目标在立项时按规模约定

五、designer-craft 与 HTML 的两层职责

表达设计：把“神韵”落到可讨论的对象

  • 快速浏览标题与图表即可抓住主判断，细读可追溯依据。
  • 章节有承接和转折，避免平均用力与材料堆叠。
  • 图形服务解释：比较、机制、趋势与不确定性选择恰当表达。
  • 留白、强调、节奏和色彩体现智见报告的克制与清晰；不靠装饰数量证明设计质量。

成文执行：两份参考成为明确规则

参考落实到 HTML/PDF 的设定
credit-policy深青主轴、暖白底、紧凑对照表、章眼左边框、规则标签；层级清楚，正文与注释保持可读
designer-paperforest-sage 色系、章节侧栏、纸面卡片、清晰信息层级和纸本节奏
共同要求语义章节、来源与图注完整；响应式屏幕；A4 打印；无裁切遮挡；正文与已审版一致；不复制历史示例事实

每篇选择主样式，另一份参考可提供适用组件，明确组件用途和规则优先级。不得机械叠加冲突版式。字号、间距、颜色、图表、页脚按执行规范实现；历史固定画布缺陷修正为响应式。

内容校验与视觉校验分开：排版变化只重跑受影响的渲染检查；正文实质变化回到内容版本。相同文件与相同规则版本的检查结果可复用；新版本用旧截图冒充验收仍禁止。

六、整体门禁放松方案

原则：只将损害真实性、核心判断或实际交付的问题设为阻断。检查服务于阶段，不要求每个内部动作都成为审批节点。每条规则只维护一处，其他材料引用。
规则类别V5 处理发生位置
固定章数、H2 逐字一致、每章六件套、固定图数取消通用硬限制，作为适用时的参考写作与设计建议
三透彻 ≥50%、固定十条增量、统一三情景取消通用配额，按核心问题和研究规模判断充分性设计时约定，内容评审判断
全部通道/每城固定探针数仅检查本题所需通道；记录实际探测，不为填表重复调用相关通道开始使用前
格式、来源加粗、固定状态词、金句与标题写法解析兼容；可自动规范化的元数据由系统处理，其余为提示本地预检
数字失真、空值当零、错误统计范围、核心推导不成立阻断受影响结论；允许删除不成立结论或明确降级，核心问题无法回答时再调整范围证据入库与内容评审
单源、未知单位、未覆盖月份记录限制与用途；无法支持相应量化结论，不一律判整篇失败证据与相关正文位置
已审版本漂移、伪造来源、越权、错误收件人与对外发布保持硬边界和明确责任系统事务与授权边界
内容遮挡、关键图表误导、PDF缺页或交付文件缺失阻断相应交付；修复与重检受影响部分成品验收
美观偏好、非关键间距、装饰数量作为建议；明显损害阅读或偏离已确认参考设定时再修正独立设计评审
重启、鉴权、网络、声明接口缺陷技术等待，有恢复条件，不扣内容修订次数、不无限循环重试Host运行层

人工决策集中在方向与正文。主证据和反证的内部产物不分别强制完整语义评审：证据接纳时自动核验，最终内容评审集中检查承重事实与推导。重要争议可提前短评，避免把错误带入写作。

评审一次集中返回全部已发现问题，区分“必须修复”“证据限制”“编辑建议”。格式预检失败不产生内容失败记录。内容修订达到约定预算后，展示剩余问题、继续成本与缩减方案，由用户决策。

七、skill 与代码改造清单

  1. 旧 98wiki-five-articles-gated-research 保留；V5 拆出设计、证据、写作、内容评审材料，各阶段只加载需要的部分。
  2. 新增 research-expression-v5，明确 designer-craft 的神韵、逻辑、阅读与图文职责；执行模块维护两份参考设定。
  3. strategy-consulting 按问题定义、假设、故事线、行动四类模块按需使用，避免每题完整套咨询模板。
  4. 新版数据通道材料移出历史故障长记录，保留方法与真实状态；以当前目录与实际回执为准。
  5. 同步修改提示词、skill、台账 schema、机器检查与独立评审材料；不只改提示词留下旧硬门。
  6. 计划预览展示每个角色的专家、skill版本、工具权限、输入输出、工作与评审职责。角色材料与执行权限分别验证，读到skill不代表工具已授权。
  7. 台账以主张、证据、计算和章节定位为中心，不再强制逐章六段精确摘录；哈希与发布记录由Host生成。
  8. 系统统一规则ID、严重程度、适用阶段与恢复方式。用已审版本包绑定后续制作；正文修订后原子更新仍未放行的下游指向，旧记录保留，旧人工确认不得冒充对新正文的确认。

八、V4 动态改写任务缺陷的修复边界

已定位的缺陷：事后创建任务缺少 produces 接口，质量契约只有 task-output；V4原子提交却要求实际文件清单与已声明清单精确匹配，造成非空提交无法通过。

  • 创建接口补充 produces，并将声明写入质量契约和成员任务输入。
  • 兼容旧动态任务：无预置模板、无文件声明且尚未评审时，首次有效提交原子登记文件清单。
  • 后续提交和修订维持该清单；模板任务、已评审契约和已发布版本不自动改变。
  • 错误明确返回期望文件、实际文件、缺项与多项；失败不扣修订次数。
  • 恢复原任务和原作者，无需新建“改写的改写”任务；非作者评审照常进行。

此兼容修复不等于V5全部门禁改造。原稿、改写稿、用户已确认正文和实际制作输入须分别标识，避免把旧稿制作完成误报为新稿交付。

九、上线顺序与验收

  1. 先恢复当前任务：修复声明接口，定向回归，部署并恢复原作者提交与独立评审。
  2. 注册V5独立版本：新skill、角色材料、观点选择与大纲演进、统一门禁表与已审包推进；保留旧版本。
  3. 隔离试跑：验证专家贡献、观点被证据修正、章节自由变化、技术故障恢复、参考样式执行。
  4. 再作为可选模板发布：展示真实覆盖与未验证项，用户可选V5或旧版。
