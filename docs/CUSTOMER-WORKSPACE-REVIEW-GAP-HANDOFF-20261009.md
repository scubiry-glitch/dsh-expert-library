# 客户工作区与独立审核页：差距和下一阶段交接

**日期：**2026-10-09  
**执行对象：**接手客户页工作区的开发 agent  
**阶段目标：**让 `/app` 内的“工作区”成为客户完成计划确认、过程审阅、报告交付的主入口，同时保留已用惯的会话、数据和报告交互。独立审核页继续可用。

## 先说结论

客户工作区已经接通真实账号、会话数据、计划编辑与确认、团队状态、私有文件和正式报告质量门；B 账号已走通 MD/HTML/PDF 报告闭环。下一阶段主要是**信息组织和状态反馈**：把旧审核页清楚的“待我确认 → 执行路线 → 当前进展 → 正式成果”搬到客户工作区，继续使用客户账号的私有授权和现有业务接口。不要重造研究引擎，也不要将旧页整包复制进新页。

当前最影响使用的三个问题：

1. **完成后仍像待启动。**工作区顶部静态写着“从讨论走向研究方案”，四阶段卡片只给简略文本；已交付报告的会话仍首先看到大面积启动说明。服务端其实已返回 `presentation.stages`，旧页会用它显示完成、未完成、不适用及总体进度。
2. **进展页被技术原文淹没。**新页将每个 `task.description` 直接放在卡片正文。B 的真实任务包含大段 `Approved artifact flow: {...}`，手机端需要长距离滚动才看完三个任务。旧页按“当前进行 / 接下来 / 已完成”分组，任务详情和模型参数按需展开，并提供关系路线。
3. **正式报告不够突出。**新页报告卡同时摆六个预览/下载按钮，下方过程档案又出现同名的 `report.md/html/pdf` 及技术文件；旧页把正式交付放在前面，过程产出收进折叠区，只保留每类关键稿的当前版本。

### 页面布局与表格的具体方向

- **桌面：**上方只保留一行研究标题/状态/主操作，紧接待办和四阶段导航；下方当前阶段占主要宽度，次级资料用侧栏或折叠区承载。旧页的任务路线和报告行式操作适合借鉴；现有客户页配色、账号导航及会话气泡继续沿用。不要重复放两套标题、两段介绍和大面积装饰图。
- **手机：**标题、待办、阶段导航须先于插画；阶段导航可以横向滚动或紧凑两行，但选中态与完成态必须同时可辨。任务默认是短列表，正式报告先出现一个清楚的“阅读报告”动作，格式与下载收在次级区域；原始描述、质量日志和过程文件按需展开。
- **数据表：**这部分是客户页独有能力，不能照搬旧审核页。沿用真实快照清单、来源与口径、表头吸顶和容器内横向滚动；调整列标题、数值/单位对齐、行高、空值、截断及查看完整单元格的方式。桌面让表格占足宽度，手机先显示数据源和查询摘要，再进入可横向滚动的表格；不可把表格压缩成无法辨认的窄列，也不可让整页横溢。样式改造应有同一份真实 B/C 数据截图作前后对照。

## 建议的完成顺序

### P0：把已打通的闭环变得可读、可用

1. **动态工作区抬头与阶段导航。**`renderWorkspace` 消费 `presentation.mode/labels/stages`，输出 `✓ / ○ / —`、总体阶段进度和当前待办数；阶段按钮保留可点击、键盘焦点和 `aria-label`。已交付会话的 hero 改成报告状态/主入口，空会话才显示引导。不要仅根据 `documents.length` 推断完成。
2. **统一待办。**从 staged plan 与尚未有 receipt 的 pending `humanChoice` 生成可点击待办项；点击切换到对应工作区页并聚焦任务。若上下文校验需要额外字段，从现有审核上下文投影中增加只读摘要，沿用服务端冲突规则。错误/超时必须提示“结果待核实”，先读最新状态后再允许重试，避免重复启动团队。
3. **团队任务压缩。**默认只显示任务名、负责人、阶段/状态、简短摘要、阻塞/质量结果；`task.description`、模型/技能绑定、原始 JSON 放折叠的“完整任务要求/技术记录”。摘要应使用结构化字段或安全的文本截取，不修改原始任务数据。任务列表分“当前进行/待确认/接下来/已完成”，已完成默认收起，保留当前选择和展开状态。
4. **正式报告与档案整理。**同一 `resultKey` 正式报告仅一张主卡；同名过程文件不得再作为普通档案重复显示。PDF 优先预览，MD/HTML 次级；文件大小/版本/发布时间/质量状态有值才展示。证据台账、质量复核、草稿和技术 JSON 放折叠档案，并提供清楚的文件类型与任务来源。质量门、私有预览、下载字节和 HTML sandbox 不变。

### P1：把旧审核页的研究路线与实时反馈接上

5. **计划与团队路线。**复用 `preview.tasks[].dependsOn` 与 `team.tasks`、`presentation.experts`，桌面显示依赖波次或简洁 DAG；点击节点联动任务详情。手机默认分组列表，可切换路线，但不要求手势缩放才能审阅。专家头像、角色、当前动作有真实状态才展示；动画只对应实际工作/交接，不循环制造“忙碌”假象。
6. **大纲版本和上下文。**计划大纲与团队发布的大纲明确标注来源和当前采用版本；待确认内容与选择在同一屏，状态和确认凭据在刷新后仍能恢复。执行中的计划不可编辑时不要给出可点的编辑入口。
7. **连接状态与事件流。**先在现有轮询上做状态差异检测及局部更新，保证展开、当前 tab、滚动、文档预览不因无变化的响应被重置。若接事件流，由客户 BFF/客户网关按会话归属鉴权并转发既有 review hub 的变更通知；断线重连、分页/游标恢复与定期全量校准要测试。事件流仅触发刷新，不把浏览器带进旧页的 token 模型。

### P2：视觉收束和回归

8. **调整布局与视觉层级。**手机首屏应先见研究标题、状态、待办和四阶段入口；大幅静态插画缩小或折叠。计划/进展/成果用同一字体、色阶、间距和按钮主次；技术信息永远次级。数据表格保留横向容器滚动、表头和来源说明，可在独立样式任务里统一视觉，但不要用截图假数据替换真实查询。
9. **双页回归。**原独立审核页仍需能看旧分享会话；新页账号权限、会话、`@`、消息动画/回执、用量、数据表格和文件预览均不退化。

## 验收清单

**功能与状态**

- [ ] 无计划、待确认计划、执行中、有待确认原稿、全部任务完成但报告未过质量门、正式交付六类状态各有明确当前状态和下一步；四阶段状态与 `presentation.stages` 一致。C 的未成稿会话绝不显示“正式报告”。
- [ ] 计划修订后旧 digest/revision 确认返回冲突并刷新；选择原稿用当前 SHA，旧 SHA 不生效；重复点击/超时刷新不产生第二支团队或第二次选择。确认前的新用户输入必须有可见复核路径。
- [ ] B 已完成报告只显示一个正式报告主入口，PDF/HTML/MD 可预览/下载，三格式字节及授权路径不变；过程档案不重复正式文件，技术 JSON 默认不展开。
- [ ] 任务默认信息可在手机一屏或少量滚动内扫读；B 的长 `Approved artifact flow` 不再直接铺满卡片，展开后仍能读完整原文；任务状态、阻塞原因、独立质量结果不被隐藏。
- [ ] 刷新、切页、连接中断与恢复后保留当前会话、工作区 tab、任务聚焦/展开、已打开文档；无变化的更新不跳回页首。额度不足沿用可见消息回执，不被“正在研究”动画覆盖。

**权限与视觉**

- [ ] B 登录能打开自己的报告；C 读取 B 的计划、团队、数据与三格式文件/预览均为 404，匿名为 401；浏览器不能指定其他客户工作区路径。独立审核页的原有效分享链仍可用。
- [ ] 320/390px 手机与 1280/1440px 桌面真浏览器检查：无页面横向溢出、无控制台异常；待办、四阶段、正文、报告按钮和数据表均可操作，键盘能到达且有清楚焦点。表格内部横向滚动允许。
- [ ] 只查看计划、数据、报告和刷新页面不调用模型、不扣模型额度；接入事件流后离线/重连不会遗漏最终状态。

**交付物：**实现代码、关键状态的桌面/手机截图、B/C 账号正反向验收记录、旧页回归记录。报告事实、数据来源、质量门及账号权限必须以真实状态核对，不用演示占位内容替代。
