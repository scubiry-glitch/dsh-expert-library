# S1 隔离运行实例与首问验收（2026-10-08）

状态：**三个测试账号的 S1 会话与首问已小范围开放。** 外部新客户仍需显式开通账号、隔离实例与额度；数据查询沉淀、报告和管理员界面属于后续阶段。

## 已部署的隔离实例

| 测试账号 | DSH 服务 | 本机端口 | 运行身份 |
|---|---|---:|---|
| `zhijian-demo-a` | `zhijian-dsh-demo-a.service` | 3191 | `zhijian-dsh-demo-a` |
| `zhijian-demo-b` | `zhijian-dsh-demo-b.service` | 3192 | `zhijian-dsh-demo-b` |
| `zhijian-demo-c` | `zhijian-dsh-demo-c.service` | 3193 | `zhijian-dsh-demo-c` |

每个实例有独立的 DSH home、工作区、服务端网关凭据和运行用户。DSH 仅监听本机；客户应用按账号的 `backend_ref` 选择固定实例，以服务端私有凭据调用网关。网关只接受 loopback 与对应实例的凭据。

模型调用由 [独立模型网关](../../../apps/model-gateway/README.md)承接。三个 DSH 实例只持有各自的代理凭据，无法读取上游模型密钥或别家凭据；模型网关只监听本机、固定上游地址、按账号预留及结算 token。`RESEARCH_ENABLED_BACKENDS` 当前仅列入 `zhijian-demo-a/b/c`，每个账号 UTC 日上限为 500000 token。其他未开通账号继续返回 `RESEARCH_UNAVAILABLE`。

## 验收记录

1. 三个服务均启动并返回网关健康检查 200；任一实例使用别家的网关凭据返回 401，运行用户不能读取别家凭据文件。
2. 三个实例分别创建空白会话、发送“请仅回复：隔离实例首问验收成功。”；各自会话收到恰当的模型答复。用自己的网关凭据查询别家实例上的会话返回 404。
3. 最初的临时共享模型凭据冒烟测试完成后，已恢复三个实例的原始凭据并删除临时备份。随后改为受限模型网关，各实例再次完成真实首问，网关按账号记录了输入、缓存命中与输出 token。实例进程、其他实例用户都无法读取网关持有的上游模型密钥。
4. 客户应用增设逐账号研究开关：未被 `RESEARCH_ENABLED_BACKENDS` 列入的账号无法通过 BFF 选择研究实例。未成功绑定 DSH 的会话索引不会出现在“我的会话”；重复的创建请求仍可重试绑定。客户应用测试 12/12、模型网关测试 2/2 通过，构建和打包通过。
5. 生产 BFF 联调以临时浏览器会话验证：A 可新建空白会话、重复创建保持同一 ID、发送首问并收到模型答复；B 在未开通时创建返回 503、访问 A 会话返回 404，B 列表不出现 A 会话。联调会话已撤销。开通三个测试账号后，经公网 `https://zhijian.meizu.life/api/bootstrap` 验证各账号 `authenticated: true`、`researchReady: true`；`/healthz` 标识 `S1-research`，旧审阅页无令牌入口返回 200。

## 扩大客户试点前的剩余门槛

- 用真实浏览器完成 OIDC 登录、刷新恢复和成员撤销回归；当前公网验收使用程序签发的短期会话，尚未代替人工浏览器验收。
- 将模型网关账本与上游账单对账，验证服务异常、中途断流、额度耗尽和跨 UTC 日的行为；当前 pending/无 usage 会保守占额。
- 完成隔离实例的重启恢复与备份恢复演练，并对带权限的旧审阅链接做回归；其他客户须按账号完成这些检查后再逐一打开开关。

## 下一阶段接入点

S2 的数据清单应由 DSH 中已经通过 dataset/provenance 校验的真实 provider 回执生成，按会话 ID 固化快照。客户 BFF 只负责账号归属核验和列表/详情代理；浏览器不提交任意表格作为“查询结果”。提及对象先从服务端已授权目录返回结构化 ID、类别与显示名，发送时重新校验授权。问题卡保留勾选项和最后一行自由文本，提交值作为结构化答案入会话，而非只在界面展示。
