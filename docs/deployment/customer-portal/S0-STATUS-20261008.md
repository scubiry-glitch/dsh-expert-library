## DSH 能力核对

| S0 事项 | 当前依据 | 判断 |
|---|---|---|
| 空白会话创建 | DSH `session/create` 接受 `workspaceId`、可预分配的 `sessionId` 与 `agentPreset`；Host 实现说明支持显式 ID 幂等采用 | 有可复用原语；需在账号 BFF 与 DSH 受控接口之间实跑，不让浏览器指定工作区 |
| 首问 | DSH `sessionController.prompt` 支持 `requestId`、队列模式；专家库 `sendReviewMessage` 已复用该入口与冷会话续接 | 有可复用原语；现有审阅接口仍要求单会话分享授权，不能作为新客户账号入口 |
| 工作区供给 | `workspace/create` 注册一个**已存在**的目录，重复注册同一路径返回既有工作区 | 客户目录需要由受信服务端创建、规范化、绑定账号并限制工具/文件范围 |
| 会话归属 | DSH workspace 是目录和会话分组；当前专家库审阅签发只依赖 Host 登录通过后定位 captain/plan/team | 未证明账号 ACL；不能仅以工作区列表隐藏实现隔离 |
| token 来源 | DSH `assistant/message` 可携带模型 adapter 报告的 `usage`；TokenUsage 区分输入、输出、缓存读写等 | 有原始字段；需验证跨子会话归集、重试去重与缺失用量的处理 |
| 报告私有性 | 现有审阅发布路径可写匿名 `/render/expert-library` 文件 | 客户版需新建私有读取与分享授权，不能沿用公开静态路径 |

以上是源码和类型契约核对，不是生产环境的双账号实测；隔离验收仍在 S0 技术闸门中。

### 2026-10-08 隔离闸门结论

已发现单 DSH 进程 + 不同 Workspace **不足以作为外部客户之间的保密边界**。Host 的 `workspace/create` 只登记目录，`session/create` 只把会话附着到该工作区；DSH 自带 `workspace-write` 沙箱限制写入位置，但其 Linux bubblewrap 实现仍把宿主根目录只读挂入，文件读取并不按工作区隔离。即使客户 BFF 正确过滤会话 API，同一运行身份的模型工具仍可能读取其他账号工作区的文件。专家库插件还会遍历所有已注册工作区和会话 cwd 来发现团队状态。这个结论来自 DSH 源码与沙箱说明，尚未对生产机做侵入式交叉读取测试；前述机制已足以拒绝把 Workspace 当作租户安全边界。

目标实施改为：客户页和账号数据库可共享一个 BFF；每个**互不信任的客户账号**分配独立 DSH 进程/容器、运行身份、工作目录与服务凭据。BFF 仍按账号映射到工作区和会话，并从服务端选该账号的 DSH 后端。领域包和公共代码通过只读发布物复用。内部同信任域演示可以临时共用 DSH，但不可据此验收外部客户隔离。后续需补容器/进程隔离、跨账号 API 与文件访问测试，然后才打开会话创建。

账号底座已落到 `apps/customer-portal/account-store.mjs`：显式开通身份和成员、服务端绑定工作区、按账号建立幂等会话索引、Cookie 与 CSRF 摘要存储、即时撤权。独立应用的 OIDC 客户端、浏览器绑定回调和登录态也已实现并由本地双账号用例验证。`pack-center/oidc` 已增加并加载第二个精确回调客户端，旧入口、新入口和错误回调均已在线检查。**S0 时点**客户页登录未启用；之后登录试点已单独发布，模型路由和真实身份联调仍未通过。

DSH 内网网关与 BFF 的新建会话、首问、对话读取接口已实现；随后在**两个独立 DSH_HOME 和两个系统用户**的真实 Host 上验证空白会话、双向网关凭据拒绝、跨账号直链拒绝、操作系统文件读取边界，见 [S1 隔离与网关](S1-ISOLATION-AND-GATEWAY.md)。首次消息被 Host 接收，但试验实例没有模型凭据，尚无模型回复。S0 更新时只把包含未启用功能的客户应用发布包更新到 `/opt/zhijian/customer-portal`，保留上一版于 `/opt/zhijian/customer-portal.backup-20261008-before-s1-code`。**当时**公网 `/api/bootstrap` 返回 `authenticated:false, phase:S0`；之后已进入 `S1-auth`。DSH 插件**没有安装到生产 web profile**；OIDC 客户端登记已在身份服务生效。

## 尚需完成才能对外开放

1. **真实账号与隔离：**S0 页面登录按钮保持禁用。身份源、账号工作区供给、空白 captain 首问、跨账号原始 API/文件/工具隔离、私有报告读取与 token 原始事件仍需实测/开发。未完成前不得让客户通过新域名访问研究数据。
2. **登录链路：**接入真实身份前验证 OIDC 回调、Cookie、CSRF、退出/撤权和跨浏览器会话恢复；源站 TLS 只完成了传输层准备，不代表身份和权限已完成。
3. **跨机连通：**以后迁新服务器时配置受限的 `DSH_BACKEND_URL`，不得直接暴露 DSH 端口到公网；完成服务认证、网络 ACL 和故障超时验证。
