## 范围与基线

- C 会话 `4a773744-cf86-4cba-a0fd-9b26d428e042` 的服务端网关只读测量：消息、提问、审批约 7–68 ms；工作区连续两次约 1452、1361 ms。网关响应约 34.7 KB，C 的当前团队 `team.json` 约 8.4 MB。

## 改动

1. 客户页在切换会话时取消旧会话的只读请求；消息、提问、审批、工作区按请求完成时间继续轮询，失败后指数退避，页面不可见时暂停。新会话的提问与审批不受旧会话在途标记阻挡。对话的发送入口不等待工作区加载。
2. 客户网关优先从已确认计划的 `appliedTeamId` 定位团队，并验证团队归属和 `planRef`；旧记录保留逐团队查找回退。只读路由摘要按团队文件的设备、inode、大小、纳秒 mtime/ctime 缓存，文件变化会重新完整读取与验证。任务修改路径仍使用 `readTeam`。
3. 同一次客户工作区读取复用审核上下文中的团队和计划，避免再次读取大文件。活动接口使用经验证的成员摘要，仍用运行中 Agent 的实时状态判定。
4. 工作区团队页和研究成果页隐藏重复的顶部专家场景，让任务路线和正式报告更早进入首屏；移除重复阶段汇总。登录页只展示实际可用的合作伙伴中心登录方式，修正 320/390px 的横向溢出。
5. 更新客户页 README 的当前功能与试点状态。
6. Nginx 为本域名记录请求耗时、上游耗时/状态、Cloudflare Ray ID 与源站请求 ID；源站响应包含 `X-Request-ID`，便于下次浏览器 HAR 与源站日志对照。
7. 首次登录状态和会话列表读取遇到网络级中断时，350 ms 后各自动重试一次；写请求与常规轮询没有立即重试，避免重复操作及故障时放大流量。
8. 将只允许客户会话通过 `customer_ask_question` 提问的保护安装到 A/B/C 三个客户 DSH profile，避免通用 `ask_user_question` 无法在客户页回答而挂起；修正 C profile 中误缩进到插入项下的 `bk-hva-007` 模型覆盖配置。
9. 把部署 `dist/` 顶层 8 个旧版页面备份移至站点外归档，目录中只保留现用 `index.html`、`app.js`、`style.css`、`favicon.ico` 和 `assets/`。
