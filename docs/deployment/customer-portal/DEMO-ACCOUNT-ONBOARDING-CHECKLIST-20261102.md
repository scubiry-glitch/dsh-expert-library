# 智见新演示账号开通清单与故障排查

更新：2026-11-03。适用于在 `zhijian.meizu.life` 增开与 demo-a、demo-b、demo-c 同类的客户账号。以实际运行配置和当前管理接口为准；本文不保存任何密码、令牌或绑定码。

## 先明确五层配置

| 层 | 需要独立的内容 | 验收依据 |
| --- | --- | --- |
| 门户账号 | `slug`、工作空间 ID、`backendRef` | OIDC 用户登录后 `/api/bootstrap` 返回正确账号 |
| 门户成员 | OIDC `issuer + subject`、该账号成员资格、角色 | 目标成员为活跃 `admin`，其他账号不继承该权限 |
| DSH 运行实例 | 系统用户、DSH home、工作区、端口、门户网关凭据、模型目录与默认路由 | 服务健康，模型首答成功，跨账号会话与文件不可见 |
| 模型网关账号 | 独立代理凭据、上游权限、每日额度、积分换算、输出上限 | 请求记入正确账号，模型候选和用量口径正确 |
| 领域包中心部署点 | 每账号独立部署点、机器凭据和私有绑定文件 | 连接正常，目标版本在该账号已安装且已启用 |

门户账号和登录用户是一对多关系。创建账号、添加成员、提升管理员、绑定运行实例、配置模型网关、绑定领域包中心、安装领域包，分别需要验收。任一动作完成都不能推断其余动作已完成。

## 开通前记录

- [ ] 记录新账号 `slug`、登录用户名、OIDC `issuer + subject`、后端别名、端口、系统用户、DSH home、工作区和负责人；逐项确认不与已有账号冲突。
- [ ] 记录要与哪个基准账号对齐，以及精确的领域包 `packId + version + releaseId`。先区分“中心安装的领域包”和基准实例本地自带的能力；后者不能通过中心目录自动复制。
- [ ] 列出刻意保留的账号差异。demo-b 的 Wind CLI、报告缓存目录和内存上限是显式覆盖项；复制 demo-c 配置时不能覆盖它们。
- [ ] 明确联网搜索授权是否与基准账号一致：当前 A/B 的模型网关 `webSearchEnabled=false`、C 为 `true`。将“保持关闭”或“按 C 开启”记录为逐账号决定，并在开通后实际验证。
- [ ] 先备份即将改动的账号库和实例配置，并记录时间、服务版本、回滚路径。凭据文件只记录位置和权限，不复制进文档或日志。

## 逐项开通

### 1. 门户账号与成员

- [ ] 在门户私有 `ACCOUNT_DB_PATH` 对应的账号库中创建账号，分配唯一 `slug`、`workspaceId` 和 `backendRef`。使用门户的 `npm run provision`，将 JSON 指令送入标准输入；不要将 OIDC 身份值放进命令行参数。操作入口见 [门户 README](../../../apps/customer-portal/README.md)。
- [ ] 用真实登录得到的 OIDC `issuer + subject` 添加成员；核对成员所属账号。不要按用户名相似度猜测 subject，也不要把 A/B 用户加到 C。
- [ ] 如果该用户需要“能力管理”，将**该账号内该用户**的成员角色设为 `admin`，确认仍为 active/enabled。当前 `provision` 脚本只有建账号、加成员、停用成员和列待开通身份；角色变更应走已审计的管理流程或范围受限的数据库事务，变更前备份、变更后只读核对账号 ID、用户 ID、角色。
- [ ] 该用户重新加载 `/app`，在自己的登录态检查 `/api/bootstrap`：`authenticated=true`、`user.accountName` 正确、`user.role=admin`、`researchReady=true`。`/manage` 是正确入口；`/manage.html` 不是公开路由。

### 2. 独立 DSH 与用量

- [ ] 为新账号准备独立运行用户、私有 DSH home、工作区、会话目录、未占用端口和 systemd 服务；复用程序代码可以，不能复用运行目录或客户凭据。隔离要求见 [实例与隔离记录](S1-ISOLATION-AND-GATEWAY.md)。
- [ ] 在门户服务端 `DSH_BACKENDS_JSON` 中把 `backendRef` 指向对应环回实例；在 `RESEARCH_ENABLED_BACKENDS` 中仅加入已验收的别名。为门户与该实例配置同一份**该账号专属**网关凭据，文件由服务账号读取、浏览器不可读。
- [ ] 比较最终生效的 DSH 设置和 systemd 覆盖项，保留账号特有的 home、端口、工作区、数据源、模型凭据和 B 的显式 Wind/缓存/内存配置；不要整份复制 C 的私有文件。
- [ ] 检查该实例 `profiles/pilot/package.json` 的 `name` 和非空 `version`。若 `cordis.patch.yml` 加载了 profile 目录下的自定义 `.mjs` 插件，请确认该插件向上找到的第一个 `package.json` 也有版本；当前 A/B/C 的 `dsh-profile-pilot` 均使用占位版本 `0.0.0`。这是本地配置包元数据，不表示升级领域包或插件代码。
- [ ] 为长时间运行的 DSH 实例设置账号私有、持久且可写的 `TMPDIR`（例如该账号 DSH home 下权限为 `0700` 的 `tmp`），并在服务重启后核对进程环境。DSH 的子进程输出可能写入临时目录；系统清理 `/tmp` 后，旧进程继续使用已删除的目录会导致实例崩溃。
- [ ] 服务启动后检查实例健康、重启后的会话恢复，再做两账号相互不可见的会话和文件检查。

### 2A. 模型配置与用量

- [ ] 在模型网关的私有配置中为该账号建立**唯一**账号 ID 与代理凭据摘要，设置 `dailyQuota`、`tokensPerPoint`、`glmEnabled`、`webSearchEnabled`、`maxOutputTokens` 及必要的 `maxOutputTokensByProvider`。逐字段与目标基准账号对照，保留经过确认的差异；不要复制 C 的代理凭据摘要或上游密钥。网关的配置校验当前要求输出上限不超过 32,768 token，修改更高上限需先验证代码与上游实际能力。
- [ ] 仅在模型网关服务保管上游密钥。目标 DSH 的私有凭据存储只放自己的代理凭据，权限 `0600`；检查 DSH 的提供方路由确实指向网关，并与网关中的账号身份匹配。模型网关仅监听环回地址；客户浏览器不接触代理凭据或上游密钥。见[模型网关说明](../../../apps/model-gateway/README.md)。
- [ ] 核对该账号 DSH 的可解析模型目录、默认预设、专家库默认模型及逐专家覆盖。`/app` 的会话模型选择只影响该会话后续消息；`/manage` 的专家模型设置影响账号实例的专家路由，两者不能相互代替。候选出现仍需用实际调用验证权限和上游可用性，尤其是 GLM/ZAI 开关与模型 ID 白名单。
- [ ] 为门户同时配置模型网关的只读用量地址和只读凭据文件（`MODEL_USAGE_URL`、`MODEL_USAGE_TOKEN_FILE`），核对“设置与用量”的账号、当日额度、已用、近七天和 token/积分显示。对齐 demo-c 的是**额度规则和显示口径**，不是复制 C 的历史用量；`tokensPerPoint` 改动会按新比例重新折算历史展示。
- [ ] 分别以目标账号新建会话，读取实际模型候选与当前选择，发送一条短消息和一条目标模型的真实请求；核对提供方、模型 ID、回复、网关账本账号归属及输出截断情况。需要联网搜索时另测 `webSearchEnabled` 和会话内的联网授权；搜索/抓取次数不计入模型 token 额度。
- [ ] 单独验收联网搜索差异：确认 A/B 的 `webSearchEnabled` 当前为 `false`、C 为 `true`；按逐账号决定调整后，在各自会话测试搜索与抓取的允许或拒绝结果，并核对不会串用别的账号额度或凭据。

### 3. 每账号绑定领域包中心

- [ ] 在 `https://packs.meizu.life` 为**每个账号的宿主实例**创建独立部署点，并分别签发一次性绑定码。开发者 `dut_token_` 只用于开发者 API；下载和安装需要宿主绑定后的 `dpc_token_` 机器身份。两者不能混用。
- [ ] 独立核对中心 ID、HTTPS origin、受信任 Ed25519 公钥。按[租户接入指引](https://packs.meizu.life/guides/tenant-setup)在目标 DSH 的管理页完成绑定。`packCenterOrigin` 与 `packCenterDir` 使用该实例自己的设置和目录；绑定结果保存在该账号私有的 `pack-center/private/connection.json`，属主私有、权限 `0600`。
- [ ] 从**该账号**的 `/manage#packs` 查看连接状态与可安装目录。核对目标 release 对该部署点可见、可下载、兼容宿主版本，目录不是 stale。若中心连接成功但目录缺目标包，检查分发授权、发布状态和兼容条件。
- [ ] 首次接入时，明确执行目标 release 的“安装并切换”，或先“仅安装”再“启用”；等待操作完成。只把更新策略设为 `download` 不会为完全未安装的包做首次安装。
- [ ] 操作请求使用当前安装 `generation`；远端安装还需当前连接 `revision` 和目录给出的 manifest、artifact、content-tree 摘要。页面会提交这些值；发生冲突时刷新连接和目录后重试，不能复用旧快照。
- [ ] 在该账号的已安装清单核对目标 `packId`、版本、`active=true`、完整性 `verified`；再从该账号新会话的 `@` 目录或宿主 `mentions` 核对实际可用。下载成功、已安装、已启用、会话可见是四个不同检查点。

### 4. 管理权限与端到端验收

- [ ] 分别以新账号的真实用户登录，验证 `/app` 显示“能力管理”，`/manage` 可进入，`/api/capabilities/center-connection` 和 `/api/capabilities/center-installations` 返回该账号数据。页面可访问不代表 API 有权限；非管理员管理 API 应返回 `ADMIN_REQUIRED`。
- [ ] 核对 `/api/capabilities/models` 返回当前账号模型目录；在 `/app` 的新会话中检查模型选择和实际首答。再检查“设置与用量”与网关账本一致，不能只凭门户下拉列表或网关配置文件判断可用。
- [ ] 用账号 A/B 各建一个**新会话**检查目标领域包和数据源。旧会话里曾发生的 403、失败消息或旧快照仍是历史记录；安装成功不会改写它们。
- [ ] 负向检查：A 用户看不到 B/C 会话、文件、用量和管理数据；B 同理。分享链接没有管理权限。管理写入必须走同源页面和 CSRF，不通过浏览器手工提交宿主服务凭据。
- [ ] 保存验收记录：账号别名、服务状态、连接状态、release 版本、安装状态、实际 `@` 目录、管理员权限、隔离结果、检查时间。只保存脱敏状态，不保存登录 cookie、密码、令牌或一次性绑定码。

## 出错时按现象排查

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| 开发者 API 请求 `/api/v1/*` 下载返回 `403 HUMAN_AUTHENTICATION_REQUIRED` | 是否把 `dut_token_` 当作机器凭据；请求是否来自受限会话沙箱 | 在宿主管理端为该实例绑定部署点，让宿主用自己的机器身份安装；不要在普通会话里代替宿主下载。 |
| 领域包中心已连接，但目录没有目标 release | 部署点是否属于当前账号，发布、分发、可下载与宿主兼容状态，目录是否过期 | 修正中心侧可见性或兼容性，再刷新目录；不要复制 C 的私有绑定文件。 |
| 目录有包，安装后 `@` 仍没有 | 操作是否完成、是否启用、完整性、宿主 `mentions` 是否刷新、是否进了正确账号的新会话 | 从已安装清单逐级核对；启用后重读目录并新建会话验证。 |
| `/manage.html` 为 404，或 `/manage` 看不到入口 | 正确路径 `/manage`；`/api/bootstrap` 的 `role`、`researchReady` | 修正当前账号成员角色和后端开通状态，然后刷新登录页。 |
| `/api/capabilities/*` 返回 401/403/503 | 登录态、账号内 `admin`、CSRF/Origin、`backendRef` 和服务健康 | 按返回码定位；不要通过关掉鉴权或共用 C 的网关令牌解决。 |
| 模型可选但调用失败，或回到意外模型 | 会话选择、DSH 默认预设、专家覆盖、网关 `glmEnabled`、模型白名单、代理凭据归属 | 沿“会话 → DSH 路由 → 模型网关账号 → 上游”逐层核对；凭据修复后以真实短请求验收。 |
| 额度或输出长度与基准账号不一致 | 网关 `dailyQuota`、`tokensPerPoint`、账号及提供方输出上限，门户用量只读连接 | 分清额度、积分换算和单次输出上限；从网关生效配置与账本验证，不以模型官方理论上限代替本机上限。 |
| A/B 与 C 的数据源或 `@` 数量不一致 | 对比中心已启用清单、本地包、数据源凭据及账号设置 | 只按明确需求单独接入缺失能力；“同一套代码”不等于相同的本地包、数据源和授权。 |
| 新消息几秒内失败、没有助手正文，反复提示“上一轮未完成”；回合错误码为 `REQUEST_EXTENSION` | 查看该账号会话的 `turn/end` 和服务日志；检查 `profiles/pilot/package.json` 是否有非空 `version`，尤其是加载了 profile 内自定义插件时 | 先备份配置包清单，按部署约定补版本字段；确认没有运行中的会话后重启**该账号** DSH，用独立新会话发短请求，核对助手回复和 `turn/end.data.reason.kind=completed`。旧失败回合不会自动续跑，应在原会话重新发送问题。 |
| 长会话执行工具时中断，服务日志出现 `dsh-subprocess-*/...-stdout.log` 的 `ENOENT` | 检查 DSH 进程是否因输出目录消失而重启、该服务运行时长、`TMPDIR` 是否仍指向受系统清理的 `/tmp` | 给该账号配置私有持久 `TMPDIR`，核对属主和 `0700` 权限；等正在执行的回合结束再重启服务，使环境变量生效。重启后做短命令与会话检查，不靠反复发送“继续”修复被中断的旧回合。 |
| 旧会话仍显示“上一轮未完成” | 对照失败记录时间，并检查当前新消息是否能完成 | 保留历史记录；当前请求已恢复时，在原会话重新发送问题。若新消息仍失败，按实际回合错误码继续排查。 |

## 本次 A/B 的已核实基线

2026-11-02，A/B 各有独立 DSH 实例、门户账号和领域包中心部署点，两个账号各自成员已提升为该账号的 `admin`；中心安装并启用了与 C 当前中心清单相同的 9 个 release，其中“城市月报” `prod.city-house-price` 为 2.5.1，完整性为 `verified`。这是配置和管理接口验收；仍应按上面清单用 A/B 真实浏览器登录完成端到端验收。

C 的 `@` 目录还包含 5 个非中心安装的本地领域能力，且有额外数据源；因此不能以 A/B 的中心清单已对齐推断其全部能力已对齐。B 的 Wind CLI、报告缓存目录和内存上限覆盖项继续保留。运行状态与版本会变化，执行新一轮开通时重新读取现场。

同日只读核对生产模型配置：A/B/C 的网关 `dailyQuota` 均为 2,000,000,000 token/UTC 日，`tokensPerPoint` 均为 7,000；`glmEnabled=true`。通用单次输出上限均为 16,384，按提供方覆盖均为 DeepSeek 24,576、GLM 12,288、ZAI 12,288。三实例的 `agent-presets.default` 均为 `zhijian`，专家模型覆盖均为相同的 9 项，且各自 DSH 凭据文件为 `0600`。**差异：**A/B 的网关 `webSearchEnabled=false`，C 为 `true`；需要按产品授权决定是否对齐，并独立验收联网搜索。上述是配置值核对，不等于三个账号的全部模型候选或真实调用均已在本次文档更新中验收。

2026-11-03 故障复核：B 的一条会话连续 8 个回合均在模型生成前以 `REQUEST_EXTENSION` 失败，没有助手正文；同账号另一条新会话也出现该错误。B 的 profile 配置包缺少 `version`，而请求扩展会读取已加载插件的所属包名称与版本。给 B 的 `dsh-profile-pilot` 补上 `0.0.0` 并重启后，独立新会话已正常回复并以 `completed` 结束。随后发现 A 同样缺少该字段，也已备份、补齐并通过新会话验证；C 原本就是 `0.0.0`。目前 A/B/C 在这个版本字段上对齐；其他账号配置仍按上面的差异逐项核对。
