## 数据链路

1. 只有 `expert_provider_call({dataset: ...})` 成功、数据集口径与 provenance 校验通过时，DSH 才把完整 provider 结果写入该客户 `DSH_HOME/customer-data/<session-id>/`。保存位置在 agent 工作区之外；单个快照上限 8 MiB。超过上限或写入失败时，工具结果附带“未能保存到客户数据清单”的警告，不把失败伪装为已留存。
2. 内网 customer gateway 仍要求环回地址、对应实例的服务凭据和本实例会话归属。只增加数据清单与快照表格的 GET 路由；浏览器没有写入任意表格的接口。
3. BFF 先以浏览器登录态查账号成员、账号下会话及固定后端，再向该实例转发清单和详情。快照详情按 100 行分页；对外只展示 provider 名称、口径、单位和查询时间，不透出 provider 传输路径。页面沿用原“数据” tab：先清单，点击后显示只读表格。

## 容量与下一步

每个客户账号对应一个 DSH 进程，账号中的多位用户和多个会话共享该进程。重启并就绪后，三个测试 DSH 的 `memory.current` 分别约 356、327、322 MiB；本轮观察到的 `memory.peak` 分别约 486、390、445 MiB。先前某些实例约 30 MiB 的瞬时 RSS 是低驻留状态，不能用来估算新客户容量。当前机器约 7.5 GiB 内存，新增客户应逐个评估内存与并发；不应按账号数无限预启动。后续实现空闲实例按需启停时，仍须保持每账号独立用户、DSH home 和凭据，且验证冷启动与会话恢复。

下一步先确定首批真实数据源及其客户权益，完成一个经 provenance 校验的实际查询和跨设备表格回归；再扩展领域包、专家的授权目录及定向路由。S3 的报告闭环可并行做接口设计，但数据驱动报告验收仍要使用真实授权数据。

## @ 目录与提问卡增量验收

- DSH 根据当前实例已注册且有有效凭据的数据源返回 @ 目录；BFF 从登录账号映射到固定实例，浏览器不提交后端地址。发送消息时再次校验提及对象，未知或未开通对象在进入模型前返回 `MENTION_UNAVAILABLE`。
- 客户会话的 `customer_ask_question` 工具把 1–3 个结构化问题挂到当前会话。客户页显示选项和末行自定义输入；用户提交经过账号归属、CSRF、问题 ID 和答案校验后，答案返回等待中的同一轮模型调用。刷新和切换设备可从实例读取待答卡；实例重启会中断未完成的卡，后续要做任务持久化恢复。
- 本地网关/提问测试 4/4、客户应用测试 12/12、两端构建通过。发布后三个试用实例网关健康检查均 200，公网 `/app` 200、匿名提问接口 401、试用账号带会话读取 200。B 试用账号的真实模型轮次完成“显示两项选择 → 提交 200 → 继续回复”；A 试用账号在同日模型额度不足时收到 `QUOTA_EXCEEDED`，未把该轮当作提问卡成功验收。测试浏览器会话均已撤销。
- 额度失败回执已补入会话投影：DSH 持久事件中的 `turn/end` 只映射安全的错误类别，不把上游错误详情给浏览器。客户页将本轮回执改为“模型额度不足”或“处理失败”，停止无限等待。A 账号的已失败会话在重启后仍投影为 `quota_exceeded`，确认刷新可恢复该状态。
