具体诊断如下：

1. [原工艺 SKILL](../knowledge/skills/zhijian-report-craft/SKILL.md) 的必读入口只指向 Markdown 骨架模板，没有指向两份 HTML。文档声称存在的工作区 shared 模板副本，在已核查的主仓及本轮 real 工作区精确路径上均不存在。
2. [渲染 SKILL](../knowledge/skills/zhijian-designer-render/SKILL.md) 仅 26 行，没有链接随包参考件、Reviewer 提示、图表模板或门禁脚本。[Reviewer](../knowledge/skills/zhijian-designer-render/reviewer-prompt.md) 把参考比对写成“如需”，执行脚本又指向当前不存在的旧 .openclaw 绝对路径。
3. [技能发现](../src/skills-discovery.ts) 提供目录及 SKILL 路径，hasReferences 只表示存在其他文件；没有自动解析必读附件或交付正文。[场景解析](../src/skills.ts) 与发现层的检索范围也不完全相同，存在“目录可见、另一入口解析不到”的风险。现有交接主要传技能路径，不能证明每个执行角色收到材料。
4. 两个示例的样式不同：政策版使用深青墨与琥珀金，成都版使用森林绿、纸本色和固定 A4 页面。示例中的部分页码做法与现行规范不同。渲染 SKILL 固定一套基础色且禁止改色，却没有完整继承原件的安全文字色和“小字不用金色”等使用边界。
5. [工艺脚本](../knowledge/skills/zhijian-designer-render/craft_gate_report.sh) 确实以 0/1 返回局部检查结果，但主要检查全文件标记、图表标记行数、文本密度和少量禁词。它不检查参考件、实际 AA、公式、PDF 或最终文件 SHA。[密度脚本](../knowledge/skills/zhijian-designer-render/craft_density_check.py) 没有匹配到 section 时仍返回成功。[图表模板](../knowledge/skills/zhijian-designer-render/chart-templates.html) 只有注释目录，没有其说明所称的 CSS/HTML 组件骨架。
6. npm 打包范围包含 knowledge，安装也递归保留内部目录；没有证据证明当前问题来自附件必然丢包。现在可证实的是发现、路径解析、任务材料交付和完整验收没有形成一条可靠链路。

**下一轮应把参考件作为有版本、有用途的任务输入，并通过实际检查确认落地。** 一份权威源管理引用规范，必要的自包含副本由构建生成并校验；按角色交付精简必读规范和选定组件，完整历史 HTML 保留追溯用途；Host 记录实际交付版本与完整性；独立审核和确定性检查绑定最终文件。材料交付、模型理解、产物合格是三个不同命题，必须分别说明证据边界。不能靠追加“必读”措辞或反复把约 220 KB 全文塞入每轮上下文解决问题。
