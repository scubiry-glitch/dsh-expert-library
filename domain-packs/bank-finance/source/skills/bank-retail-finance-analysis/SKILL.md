# 银行零售金融分析

用于银行零售业务研究、经营诊断、同业对标、产品分析、交叉销售、专题汇报和策略设计。

核心框架：

> 战略层决定方向，客群经营层决定对象，产品层决定武器，资产层决定结果，风险层决定边界。

## 先确认任务

识别用户要解决的问题，不要默认五层平均展开：

- 全景研究：五层完整分析。
- 经营诊断：从结果和异常出发，跨层追因。
- 同业对标：统一机构范围、时间、指标口径后比较。
- 产品专题：以产品层为主，联动客群、资产和风险。
- 交叉销售：使用 `STP → 4P → 4C → 服务3P` 专项链路。
- 策略设计：从战略目标出发，形成行动、指标和约束。
- 材料撰写：先确认受众、篇幅、场景和交付格式。

信息不全时列出必要假设并继续；只有缺失信息会改变关键结论时才追问。

## 证据纪律

1. 区分事实、推断、假设和建议。
2. 财报、监管披露、官方公告、产品条款优先于媒体和二手材料。
3. 涉及机构、产品、利率、规模、风险指标和政策时，标明数据期与口径。
4. 不把集团、银行、零售口径混用；不把余额、发生额、客户数混用。
5. 同业比较先检查可比性；不可比时说明差异，不做伪精确排名。
6. 缺少数据时列出待验证项，不虚构数字、客户行为或因果关系。

## 五层框架

### 1. 战略层：方向

回答零售业务为什么做、做什么、做到什么程度：

- 定位：零售在全行收入、利润、负债、资产和客户生态中的角色。
- 目标：规模、收益、结构、客户、资本效率与风险之间的优先级。
- 资源：资本、资金、渠道、科技、数据、人员和组织投入。
- 能力：客户洞察、产品创新、定价、风控、运营和服务能力。
- 约束：监管、资本、流动性、风险偏好、区域禀赋与竞争格局。
- 执行：目标如何分解到客群、产品、渠道、区域和队伍。

至少形成：战略选择、资源配置、关键矛盾和衡量指标。

### 2. 客群经营层：对象

分析客户是谁、处于什么场景、如何持续经营：

- 分层：生命周期、收入/财富、职业、家庭、区域、风险和价值分层。
- 场景：代发、消费、住房、出行、教育、养老、医疗、经营和跨境等。
- 旅程：获客、识别、首购、交叉销售、活跃、提升、留存、流失挽回。
- 渠道：网点、客户经理、手机银行、远程银行、开放平台与生态合作。
- 销售管理：名单、线索、商机、过程、产能、激励、合规和复盘。
- 指标：有效客户、活跃率、AUM、产品持有数、转化率、留存率、单客贡献、获客成本。

避免只按资产余额分层；说明不同客群的需求、价值、风险和服务成本。

### 3. 产品层：武器

#### 产品定位

覆盖存款、财富、支付、信贷和场景类产品，明确每个产品解决的客户问题及其经营角色。

#### 产品要素

按需分析目标客群与准入、利率/费率、额度、期限、还款方式、担保增信、权益服务及全流程体验。

#### 产品结构

识别产品在组合中的角色：

- 引流产品：降低首次接触门槛。
- 转化产品：推动客户建立主办关系。
- 收益产品：贡献利差、中收或综合收益。
- 留存产品：提高活跃、黏性和迁移成本。

同一产品可承担多种角色，但要说明主次和适用客群。

#### 产品协同

用“触发场景 → 主产品 → 关联产品 → 客户价值 → 银行收益 → 风险约束”描述协同链路。例如：

- 代发带动支付、存款、消费贷和财富。
- AUM经营带动财富配置与高端权益。
- 经营贷带动结算、代发和企业主个人经营。
- 信用卡带动支付活跃与消费场景渗透。

不得把产品简单捆绑当作协同；检查客户适配、销售合规和综合收益。

#### 产品竞争分析

比较利率/费率、额度、期限、审批效率、准入、场景、渠道、服务、权益、风险容忍度和综合成本。最终回答客户为何选择、银行为何能持续提供、优势是否可复制、增长是否依赖补贴或风险下沉。

### 4. 资产层：结果

按揭、信用卡、消费贷和经营贷分别分析，不用单一逻辑套用：

- 规模：余额、增量、份额、客群和区域集中度。
- 结构：产品、期限、利率、担保、渠道、用途和客户结构。
- 收益：定价、资金、运营、信用和资本成本及综合收益。
- 风险：逾期、不良、迁徙、核销、回收、Vintage及集中度。
- 周期：利率、地产、就业、消费、产业和区域周期敏感性。
- 久期与流动性：重定价、提前还款、稳定性及资产负债匹配。

评价资产时使用风险调整后收益，不只看名义利率或余额增速。

### 5. 风险层：边界

覆盖全生命周期：

- 形成：宏观、行业、区域、客群、产品、渠道、欺诈与操作风险。
- 准入：政策、评分、反欺诈、额度和人工策略。
- 定价：风险、资金、运营、资本成本及目标回报。
- 监测：预警、逾期、迁徙、Vintage、滚动率和集中度。
- 处置：提醒、重组、催收、核销、不良转让和资产证券化等。
- 压力测试：情景、传导变量、组合损失、资本与利润影响。
- 治理：风险偏好、模型治理、数据质量、消费者保护和合规边界。

风险不是末端补充项；每项客群和产品策略都要回填风险约束。

## 交叉销售专项框架

交叉销售不单独只用某一个营销模型。标准落地链路：

> STP分层定位 → 4P盘点产品 → 4C设计客户营销 → 服务3P优化转化

### 1. STP：必备前置

用于存量客户分层、识别交叉潜力和形成客户方案，属于战略与客群经营的连接器。

- Segmentation：按资产层级、生命周期、现有持仓、行为活跃、场景、渠道偏好和风险适配细分。
- Targeting：锁定已持有A产品且对B产品存在真实需求、适配条件和转化可能的客户。
- Positioning：定位为客户问题或资产方案，不定位成单一“卖卡、卖理财”。

示例：已有房贷的工薪客户，可定位为家庭现金流与稳健配置客群，再判断信用卡、小额理财或保障产品是否适配。

### 2. 4P：银行内部产品盘点

4P是后台产品矩阵工具，不直接替代对客营销：

- Product：梳理存款、信用卡、基金、保险、贷款、贵金属等产品池及组合关系。
- Price：梳理费率、利率、资产达标权益、组合优惠及银行综合收益。
- Place：梳理网点、手机银行、客户经理、远程渠道和生态触点。
- Promotion：梳理积分、权益、活动和内容触达。

产出必须是“客群—场景—主产品—关联产品—渠道—规则”矩阵，不能停留在产品罗列。4P属于卖方视角，不能单独用于解释客户为何愿意购买。

### 3. 4C：客户交叉营销核心

用于存量客户转化，以客户需求而非银行产品库存为中心：

- Consumer：识别未满足的金融需求。储蓄客户可能需要增值配置，代发客户可能需要现金流、定投或信贷，但不得把相关性直接当需求。
- Cost：评估客户的资金、费率、时间、认知、风险和机会成本，不把“优惠”局限为降价。
- Convenience：减少重复资料、流程跳转和渠道割裂，支持一站式或线上便捷办理。
- Communication：采用双向诊断、方案解释、回访和持续服务，避免单向轰炸式推销。

4C输出：客户需求假设、验证问题、价值主张、成本说明、办理路径、沟通节奏及拒绝后的停止规则。

### 4. 服务3P：服务转化保障

金融服务高度依赖人员、流程与可信证据：

- People：客户经理、理财经理、柜面和远程团队的需求识别、专业说明、转介及合规能力。
- Process：线索触发、适配校验、授权、办理、回访、投诉和退出流程。
- Physical Evidence：手机银行资产看板、资产配置报告、产品说明、风险揭示和网点服务物料。

有形展示用于增强理解和信任，不能代替产品适当性说明或制造收益保证。

### 5. 合规与客户保护闸门

交叉销售全程检查：

- 客户授权、隐私和数据最小化使用。
- 产品适当性、风险承受能力和销售资质。
- 禁止强制搭售、误导宣传、默认勾选和隐藏成本。
- 贷款、保险、基金等产品的独立风险揭示与冷静决策空间。
- 明确客户拒绝、退订、撤回授权和投诉渠道。
- 激励机制不得只按销量驱动，应纳入留存、投诉、撤单和风险表现。

### 6. 交叉销售指标

分层观察，不只看成交量：

- 机会：目标客群规模、需求命中率、合格线索率。
- 过程：触达率、响应率、诊断完成率、办理完成率、转介效率。
- 结果：交叉销售率、产品持有数、AUM/活跃提升、综合收益、留存率。
- 体验：拒绝率、退订率、投诉率、撤单率、服务满意度。
- 风险：适当性例外、早期逾期、退保/赎回、欺诈和不良迁徙。

比较实验组与可比对照组，避免把自然购买归因于营销动作。

## 跨层诊断

不要输出五个互不相干的章节。至少检查：

1. 战略目标是否被客群选择支撑。
2. 客群需求是否被产品组合覆盖。
3. 产品增长是否转化为可持续资产和收入。
4. 收益是否覆盖资金、运营、风险和资本成本。
5. 风险边界是否反向约束战略、客群与产品。
6. 组织、渠道、科技和数据能力是否支持执行。

出现异常时使用“现象 → 直接原因 → 跨层根因 → 证据 → 影响 → 动作”追因，不把相关性直接写成因果。

## 建议形成方法

每条建议包含：问题或机会、目标客群与场景、产品或经营动作、责任主体与能力、观察/结果/风险指标、时间与优先级、前置条件、合规边界和失败信号。

## 默认输出结构

1. 执行摘要：3–5条关键判断。
2. 分析范围、数据期、口径和假设。
3. 五层分析或与问题相关的重点层。
4. 跨层关键矛盾与因果链。
5. 机会、风险及同业启示。
6. 分阶段行动建议。
7. 指标体系和验证方法。
8. 数据缺口、待核实事项与来源。

交叉销售专题额外输出：STP客群卡、4P产品矩阵、4C营销方案、3P服务设计、合规闸门和指标漏斗。

## 质量检查

- 是否明确回答核心问题。
- 是否覆盖产品层，而非只谈客群与资产。
- 是否统一数据期、范围和指标口径。
- 是否给出跨层逻辑并区分事实、推断和假设。
- 是否按资产类型体现不同久期、收益、风险和周期属性。
- 是否将STP、4P、4C、3P用于各自适合的环节。
- 是否从真实需求出发，而非用客户标签直接推断需求。
- 是否把产品协同误写成强制捆绑。
- 是否同时评价客户价值、银行收益、服务体验与风险。
- 建议是否可执行、可衡量并包含消费者保护边界。
