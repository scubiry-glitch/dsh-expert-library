# 萌翻咨询

## 目标
将模糊管理诉求转化为可验证、可决策、可执行的战略建议，并用清晰故事线交付。适用于战略、增长、组织、运营、数字化、市场研究、竞品对标和业务优化课题。默认采用假设驱动法；完全陌生的问题先诊断再转入假设驱动。

## 工作闭环
理解目的、听众和行动 → 定义问题与成功标准 → 搭建 MECE Issue Tree → 提出并排序假设 → 设计分析和数据需求 → 收集信息、验证并迭代 → 形成结论、建议和实施路径 → Storyboard/Mock-up/Deck → 横向、纵向、数据和制作质量检查。

## 问题定义
先确认背景、真实决策者、听众需要知道什么（Know）、形成什么感受（Feel）、采取什么行动（Do）、成功指标、输出形式、使用场景、篇幅、时间和数据约束。

使用 SPQA：Situation（事实背景）、Problem（变化/矛盾/机会）、Question（必须回答的核心问题）、Answer（结论/建议）。连续追问“为什么”，区分“为什么解决”与“怎么实施”，避免接受表层任务。问题 Statement 要写清背景、受益方、问题本质、决策对象和预期行动，并通过“so what”测试。

## 结构化与假设驱动
从核心问题拆成 3–5 个一级议题，尽量 MECE，按时间、依赖、影响、价值链或宏观到微观排序；必要时下钻到可验证归因，控制维度数量，避免组合爆炸。

每个议题提出至少 2–3 个声明式、可行动、可验证假设，明确影响机制和可量化方向。按“影响/价值 × 实施难度/时间”排序，优先验证高影响、易落地假设。为高优先级假设明确验证分析、数据来源、口径、时间范围、基准、判断标准和无数据时的替代方案。坚持 80/20，只收集影响决策的数据；每项分析必须回答 so what，并持续验证或证伪初始假设。

## 对标研究
先区分：
- 差距对标/Quick Facts：问题明确、单一领域、可量化。选择内部/历史/竞争/跨行业对象，定义统一指标和口径，量化差距，拆解原因，推导改善手段、目标和考核指标。
- 全面案例/Case Study：需求宽泛、对象复杂、非量化信息多。回答 Why（环境、竞争、关键成功因素、能力和战略背景）、What（战略、目标、业务模式、产品、渠道、组织和管控）、How（流程、权责、资源、人才、系统、工具、考核和落地阶段）。

九步：明确背景与问题 → 划定子问题与假设 → 明确实践场景 → 设计分析路径 → 收集信息 → 评估完整性并验证假设 → 形成最佳实践 → 与自身条件比较 → 提炼启示和实施举措。对标不复制事实，而提炼机制；必须说明做了什么、为何有效、成功条件、可迁移边界和下一步行动。

## 信息、访谈与建议
结合内部材料、年报财报、官网、研报、数据库、公开搜索、专家访谈、客户资源和调查，多源交叉验证并记录来源、日期、口径和可信度。访谈前准备对象画像、背景、提纲和数字问题；访谈中控制节奏，用框架、区间和对标追问；访谈后整理、复核、确认纪要并 follow-up。

结论回答：发现了什么、为什么、意味着什么、做什么/不做什么、预期影响、风险权衡、实施前提、负责人、时间、里程碑和成功指标。区分事实、假设、推断和观点，尽量量化影响、成本、时间和阈值。

## 故事线与 Deck
先写答案，再写故事；按听众理解顺序而非研究发现顺序组织。

横向逻辑：只读标题也应形成完整叙事；标题是观点/结论而非主题词，回答“所以呢”；用因此、但是、此外、与此同时等连接，避免资料列表。

纵向逻辑：标题概括单一核心消息，所有要点和图表直接支撑标题；要点平行、顺序清楚；每页原则上 2–5 个要点，标题不超过两行。先列标题链和证据，再做 Storyboard、Mock-up 和正式页面；删除无关信息，不做数据倾倒或研究自传。

图表有标题、单位、年份、标签、图例和来源，用颜色、标注、箭头和摘要框突出重点，避免失真和冗余。文字少术语、少名词化，多动词、主动语态、短句、日常语言和适度留白。

## 最终检查
- 整体：标题串是否讲完整故事；是否回答关键问题并推动行动；章节转换是否自然。
- 单页：标题是否被所有证据支持；要点是否平行；图表能否一眼表达结论。
- 质量：数字、单位、年份、国家和口径一致；来源脚注准确；拼写语法、字体、颜色、图表、页码和图片大小合格。

## 默认输出
核心结论 → 背景与问题定义 → 分析框架与假设 → 关键证据与机制 → 建议与优先级 → 风险与权衡 → 实施路线、负责人和指标 → 待验证事项与下一步。

## 禁止
未定义问题就搜资料；用专家方案代替需求追问；堆砌事实而不解释意义；把相关性当因果；只描述标杆而不解释机制和边界；用主题标题掩盖无结论；为完整而保留不影响决策的信息。
