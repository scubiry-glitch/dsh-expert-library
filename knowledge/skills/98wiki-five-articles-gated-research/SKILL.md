# 98wiki 五篇大文章 · 质量门控研究漏斗

## 目标
将98wiki五篇大文章从“新闻汇编/观点简报”升级为可持续的深度研究产品。任何选题先过选题门，再进入论点卡、深度研究、反方压力测试和HTML5→PDF交付。

## Phase 0：选题前置门控

每个候选选题必须先填写门控卡：

- 结构性问题：明确机制、矛盾、边界、路径或悖论，不接受“某政策发布/某项目进展/是否有效”的单事件题。
- 新知识空间：列出预计可获得的外部新事实、数据、案例、政策或公司动作；预计少于10条直接打回或降级为观察题。
- 内部密度：检索98wiki本地归档、INDEX、项目文件、知识图谱和故事线，记录命中节点数N、加权信号S、关联故事线数L、既有报告数R；N=0时必须标注“新主题”，不能假装有内部积累。
- 反共识：提出至少一个可证伪主张，并写明若判断错误的损失。
- 决策使用者：明确责任部门、具体决策动作、规模/质量/风险/资源中介的影响路径。
- 可得性：至少两个关键数据当前可获得；等待90天以上才能验证的题只能列前瞻题并附验证协议。
- 去重：与近30天选题和报告做语义去重；重复题必须给出明确增量。

选题不满足任一硬门，不得进入研究队列。输出选题时同时输出门控表，不只输出标题。

## Phase 1：立项论点卡

在动笔前先做10分钟证据扫描，形成论点卡：

1. 一句话可证伪结论；
2. 至少3个关键数字，写清来源、日期、统计口径；
3. 数据缺口清单；
4. 至少1个最强反方观点；
5. 门控判定：GO / CONDITIONAL / NO-GO。

外部新知识粗数至少6条才能进入深度研究；最终交付必须达到10条。

## Phase 2：深度研究硬闸

### A. 外部增量门

外部新知识不得少于10条。新知识包括：本次研究新获取、可追溯到外部来源、且不重复98wiki已有知识库的事实、数字、案例、政策条款、竞品动作或研究结论。

交付报告末尾必须有“外部增量清单”，每条包含：内容、来源、发布日期/访问日期、相对98wiki既有内容的增量说明。单方宣传资料不得独立支撑关键结论。

### B. 三透彻展开门

报告正文中“研究展开”不得低于50%，并且必须分别完整展开：

#### 1. 引假设
至少3个前提假设。逐一回答：假设是什么、依据和口径、成立概率/证据强度、最脆弱处、失效后的结论变化。

#### 2. 推导
把假设到判断的机制链条逐步展开。必须包含：参与者/利益相关方、传导路径、单位经济或量化中间步骤、关键变量、敏感性测试、可能的反转点。

#### 3. 未来预演
至少基准/乐观/悲观三情景；每个情景给出触发条件、3个月/1年/3年时间线、可观测验证指标、反方落地条件和止损线。

内容比例按正文字符数或段落数计算：三透彻模块合计≥50%；核心判断、背景、结论、行动建议等骨架≤50%。比例未达标必须补写，不能只靠增加标题或来源清单凑数。

## Phase 3：证据与反方门

- 关键结论至少两个独立来源；只有单源时必须显式标注。
- 每个数字写来源、口径、日期；内部演示数据、政策规则和项目结论严格分开。
- 成稿前至少两个反方观点，分别说明反方成立条件和结论如何变化。
- 明确报告薄弱点，不得使用“建议进一步研究”掩盖证据缺口。

## Phase 4：战略收口

按照五维框架收口：

1. 规模：市场容量、增量、渗透率或单位经济；
2. 质量：服务质量、资产质量、客户质量或运营效率；
3. 风险：授权、合规、数据、信用、声誉和执行风险；
4. 资源中介：从信息、数据、能力、连接、决策支持到交易执行的增量；
5. 行动：按立即、本季、观察三档，给出责任部门、动作、指标和停止条件。

## Phase 5：HTML5→PDF交付硬闸

每一份完整研究必须生成同名HTML5源文件和PDF成品，默认存放（**知识库本体** `/root/.openclaw/workspace/98wiki/projects/`，即 98wiki 贝壳域知识库）：

`/root/.openclaw/workspace/98wiki/projects/{topic}/{yyyymmdd}_{title}.html`
`/root/.openclaw/workspace/98wiki/projects/{topic}/{yyyymmdd}_{title}.pdf`

路径约定（2026-08-23 确立，消除 work/98wiki 混淆）：
- **本体唯一**：`/root/.openclaw/workspace/98wiki/` 是 98wiki 知识库权威源（feishu 归档 + projects 成品 + documents.json 图谱 + AGENTS.md 规则）。
- **产出暂存区**：插件工作区 `work/outputs/projects/`（原 work/98wiki，已更名去混淆）只做加工台；任务产物先写暂存区，**定稿后必须回流本体** `/root/.openclaw/workspace/98wiki/projects/{topic}/`，并在该目录写/追加 INDEX.md。
- 回流后 `chown wiki99:wiki99 <file>`；写入 feishu/ 必须同步更新 feishu/INDEX.md。

HTML要求：A4打印布局、贝壳蓝/白为主色、可读图表、页脚页码、来源可追溯。PDF生成后必须做真实渲染检查：至少检查桌面宽屏和A4页面截图，确认无文字遮挡、无责任部门/来源被裁切、无页面溢出。检查记录和SHA-256一并归档。

未同时存在HTML、PDF、检查记录三项，不得宣称交付完成；只生成群消息或Markdown属于未完成状态。

## Phase 6：交付前检查清单

- [ ] 选题门控表已归档
- [ ] 论点卡已归档
- [ ] 外部新知识≥10，增量清单已列
- [ ] 三透彻模块合计≥50%
- [ ] 5W2H完整，未删where/how/how much
- [ ] 至少2个反方观点及回应
- [ ] 数字有来源、口径、日期
- [ ] HTML与PDF同名存在
- [ ] PDF真实截图检查通过，无遮挡/溢出
- [ ] 检查记录、哈希、INDEX已写入

## 触发
收到选题后，先输出门控结果和论点卡；GO或用户明确接受CONDITIONAL后，才开始完整研究。
