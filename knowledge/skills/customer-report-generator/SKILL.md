# 客户报告生成

先回答用户的问题，再决定需要多长的报告。本技能只使用当前账号、当前会话中已授权的快照，不增加数据源或文件权限；用户明确指定的目标和交付形式优先。

## 先判断能回答什么

读取所选快照的来源、查询时间、实际覆盖条件、行数、单位和警告，并与用户当前问题对照。区分展示样本、总体、单时点和时间序列；不要把检索 `period`、召回数或推荐 TopK 当作实际时期过滤、总体或随机样本。

如果快照不足以回答问题，先说清它能支持的结论。同一会话有更合适的已授权快照时，说明差异并让用户选择；未经选择，不擅自换源或混合。缺失的字段、代表性和历史数据不能补造。

## 按证据决定篇幅

- 单时点、少量展示结果或非代表性样本：默认做一到两页数据简报。第一页给结论、样本边界和最有用的事实；必要的明细与来源放后面。只计算对问题有用的指标，不为凑篇幅加入相关系数、四分位、重复表格或固定章节。
- 用户明确要求深入研究，且数据能支撑：再拟简短目标、来源、主要判断、大纲和交付件；按当前 Host 已启用的适用工艺与报告契约执行。需要新增查询时先走现有授权与快照保存流程。
- 若用户只要即时解释，直接答复；只有需要下载或分享时才制作文件。交付格式按用户要求与 Host 的实际能力确定。

Host 要求计划确认时，提交最小可核对的计划并等待确认。不要为了满足模板把小样本扩成多章研究，也不要伪造工艺选择、检查结果或审核记录。

## 交付检查

关键数字回到快照核对，说明计算口径；限制只在读者需要的位置讲清，不逐章重复。检查最终交付文件的第一页、图表和分页：图形长度、颜色、标注须在实际 PDF 中成立，不能出现大面积空页或孤立段落。正式报告按所选工艺完成独立复核；任何机器检查通过都不能代替问题适配和实际阅读检查。

用户认为成品不好时，先重新审视目标、数据和内容结构，再决定是否改视觉；通过修订任务处理已冻结版本，不把旧版正文永久锁死。
