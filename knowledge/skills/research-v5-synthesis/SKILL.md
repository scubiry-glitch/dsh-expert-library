# 观点选择与研究方向

阅读每位选中专家的 view.md，保留重要分歧。向用户展示可理解的候选观点、各自价值和证据缺口，推荐一个方向。每个候选说清与常见解释的差异、现有证据、最强反例，以及下一步哪条证据能区分竞争解释；没有鉴别力的论点不要为了凑数列入。不要让用户审批固定章节目录。

在 viewpoints.md 归并各专家已取到的共同原始事实：逐项列来源与回执、采集时点、地区、指标定义、时间窗口、单位、冲突口径和未知项。后续专家优先复用同一批原始数据，不把重复转述当独立证据；关键结论仍须抽查原来源并独立重算。共享表缺失、过期或口径不适用时可重新取数，说明原因。

输出 viewpoints.md；在文末放 viewpoint-options 代码块，其内容是实际候选观点标签组成的 JSON 字符串数组。每个标签须在正文解释；用户将直接选择这些标签，不是占位 A/B/C。允许一个有充分理由的候选，不强制三选一。

## 提交

遵循 Host 的 current_action，以本任务发布声明为准。在原任务同一 attempt 内修订，不为提交方式错误新建替代任务。内部材料由 Host 校验并锁定后自动流转；只有正文和成品进行独立评审，不把内部材料称为已审结论。提交失败按具体错误重试，不能伪造回执。
