# 智见点评·行业研究报告模板（五件套骨架版）

> 沉淀自《一场"角色重写"：房地产金融 1+N 新政对行业参与主体的影响》v5.4 全流程（2026-08-29）。
> 适用：政策文件群点评、行业/主体影响分析、多主体结构化研报。篇幅 45-70KB md、PDF 20-25 页档、PPT 30 页档为最佳工作区间。
> **本文件是 skill `zhijian-report-craft` 的引用模板**（样式与结构规范）；质量/行文/数据的执行规则见该 skill 的 SKILL.md。

---

## 一、总体结构：总—分—总 + 卷首速览

```
卷首速览（一页读完：N 行结论表[主体|一句话结论|关键数字] + 核心判断 3 行 + 预言/风险一览 + 总纲金句）
总论（4-6 屏：钥匙 → 三重错位/结构性原因 → 为什么是这个形状 → 为什么是现在 → 体系地图表 → 数据底座表 → 补充数据 → 观察清单）
分论（每主体一章，五件套骨架，见二）
总结（收口六件套：三重再分配 → 风险产权/理论定位 → 三层付费者 → 可证伪预言表 → 失灵变量排序 → 传导时序 + 数据互证 + 最大不确定性 + 收束金句）
结语表（N 行：主体 | 新身份 | 一句话净效应）
来源披露（逐项口径 + 指标代码 + 四级标注说明 + 评审说明）
```

**要点**：①卷首速览是给 30 秒读者的，结论表每行必带一个关键数字；②总论回答"为什么是现在/为什么是这个形状"，必须有数据支撑（利率-余额背离是经典论证形）；③总结必须回到总论的三要素做闭环，并把全文推到一个可引用的"定价/说明书"级金句。

## 二、章节五件套骨架（每主体一章，全书同构）

| 件 | 内容 | 形态 |
|---|---|---|
| ① 一句话定位 | 金句作章眼（如"银行审的不再是财报，是工地"） | 引言块（accent 左边框） |
| ② 角色对照卡 | 旧角色 vs 新角色，3-4 行（岗位/审什么/收入/责任等维度自选） | 两列小表 |
| ③ 条款依据 | 引用具体条文，逐条列清，条号可溯源 | 紧凑列表（条款 tag） |
| ④ 推论与数据 | 3-5 条编号推论，**每条必须带数据或测算**；反直觉推论显式标"研判推断" | 编号论述 |
| ⑤ 机会与风险 | 各一句话，风险指向总结的失灵变量编号（→总结·失灵①） | 虚线胶囊单行 |

**要点**：①骨架是"结构清晰"的来源——翻到任何一章视线落点相同；②推论写法="条款 → 二阶后果 → 数字锚"，禁止无数据推论；③章名用"从 X 到 Y"身份转变句式。

## 三、点睛图规范（每章一图 + 总论/总结各 1-2 图）

- **铁律：凡 md/权威源无数字不得绘制**；定性示意图必须在图内标注"定性示意"。
- 选型对照表：

| 内容形态 | 图型 |
|---|---|
| 新旧对比（两项指标） | 对比条 / 零轴发散条（京宁分城对比范式） |
| 时间序列 | 折线（未披露月份只连锚点+图注"中间月份未披露"） |
| 水位/边际影响 | 水位图（基线+冲击+对冲后净值，标"估算"） |
| 流程/传导 | 链条流程图 / 循环图（闭环用环形箭头） |
| 多主体约束 | 三方对比卡（✓能力｜约束，含考核红线数字） |
| 进出场/格局 | 天平图 / 灯下图 / 卡阵（2×4 grid） |
| 风险排序 | 阶梯图（定性排序，不编权重） |
| 概率判断 | 区间标尺（中位+区间） |
| 全周期产品线 | 四段接力时间轴（各段期限/成数入图） |

## 四、视觉 register（finesse-ui 五轴）

- **色板**：深青墨 `#0e6a55`（ink-teal，主）+ 琥珀金 `#a9741f`（amber，强调）；警示色仅用于"被切/出局"段。
- **五轴坐标**：ink-teal+amber / 字重 700·400 / report-rail 布局 / CSS-only 图表 / policy-print 质感（SOUL 6 · SPECTACLE 2 · DENSITY 7）。
- **组件语汇**：金句引言块（4px 左边框 accent 条）→ 角色对照小表 → 条款琥珀 tag → 推论编号 → 机会/风险虚线胶囊；hero 封面横幅（深青底白字或白底深青题字+数字条白卡**不透明**——半透明卡会被对比度检查器误判）。
- **weasyprint 坑**：grid 列宽会塌陷，多列数字条一律用 flex。

## 五、封面与封底（PDF 24 页档范式）

- **封面（第 1 页，无页码）**：品牌行（98wiki ｜ 智见点评 · 行业研究）→ 衬线特大主标题 → 副标题 → 版本行（完整报告 vX · 日期）→ 琥珀金句带一句 → 白卡四格关键数字条（每格一个数+口径行）→ 底部章节导览行。**封面数字必须全部 md 在案，不得为封面新造。**
- **封底（末页，无页码）**：收束金句 → 版本信息块（版本/日期/数据口径/评审说明）→ 免责一行（"行业研究，不构成投资建议；测算/估算/研判推断非官方统计"）→ 品牌。
- **页码**：@page 命名页置空封面封底页边框，正文 N/总页数 重排；PDF 大纲保持全章节标记。

## 六、语言风格规范

1. **平实短句**：一句一个断言；长句拆短；术语随手白话解释（如 RWA→"风险加权资产"直接说白或括注）。
2. **金句密度**：每章至少 1 句可引用金句（章眼位）；全书收束金句要能脱离上下文传播。
3. **边界钉死**：每个乐观判断后钉边界（"收窄≠转正""先行个案≠全国""准入≠激励"）。
4. **去过程痕迹**：正文零版本号、零修订清单、零专家名/轮次标注；评审信息只在文末来源披露一行带过。
5. **命名纪律**：行业分析不得以单一公司命名主体（"经纪行业"而非"贝壳式经纪"），个别公司只作案例参照并可加"参照不等于豁免"式提醒。

## 七、数据纪律（不可妥协）

1. **数字四级标注**：测算（模型算）/ 估算（量级推断）/ 研判推断（分析性判断）/ 待补（观察清单项）——正文每个非引用数字都要落到一级。
2. **来源可溯源**：宏观数据 Wind EDB 带指标代码；合作数据源（如 zyt）注明口径（如"internal 对内版/external 指数化首值=100 禁当绝对量"）与趋势性/绝对量属性。
3. **编数字比不回答更严重**：数据不可得时如实标注，绝不编造。
4. **量值脱敏规则**：委托方要求不公开绝对量值时，仅保留趋势表述（"同比连续 N 个月为正"），渲染管线加禁例 token 校验（0 命中才可发布）。
5. **多源纪律**：Wind 为主定量源，合作通道数据作趋势性补充；两者冲突时在来源披露中说明。
6. **三通道引用约定**（Wind CLI 自然语言优先+指标代码溯源 / zyt dataView 口径+失败三态 / beike 凭据与未配置披露）——详见 skill `zhijian-report-craft` SKILL.md §2.7。

## 八、质量门禁（发布前全过）

| 门 | 标准 |
|---|---|
| 文字 | 禁例 token 0 命中（量值/过程痕迹/错误命名）；品牌行/金句/章节标记逐项在位 |
| 数字 | 交付物与 md 逐 token 一致，零新增（关键锚点清单 grep 28-70 项） |
| 设计 | finesse 检测 P0=0（P1/P2 尽量清零）；playwright 1280/375 双视口 0 溢出/0 裁切/0 重叠；锚点零死链；对比度 AA 0 失败 |
| PPT | pptfast validate OK + audit 0 findings；全页 speaker notes；dense pacing 页数上限内 |
| PDF | 页数在目标档；页脚品牌+页码逐页；章节大纲逐项命中（pypdf 验证，勿数原始字节） |

## 九、渲染管线与版本协作

```
md（唯一权威源）→ HTML（finesse-ui register）
              → PDF（weasyprint，A4，98wiki 页脚，封面封底 @page 命名页）
              → PPTX（pptfast，vermilion seed=日期，全页 notes）
              → sha256sums + shots/（1280/375 全页截图）+ deck/（可复渲染工程）
              → 发布：HTML 走 render_publish（外链 slug 稳定，覆盖=内容升级）
                      PDF 用 cp 到 /var/www/dsh-render/<团队id>/ 即得同域下载链（发前 curl -I 验 200）
```

- **多版本并存**：文件命名带版本（`_v5/_v52/_v54/_final`），外链 slug 一版一个，**绝不覆盖历史链接**；同名覆盖仅用于同一版本的迭代。
- **融合纪律**（多专家评审后）：keynote 先行、分歧观点降级为"边界条件/风险提示"、概率用区间+中位聚合（附各家区间）、修订只改 md 单源。
- **渲染任务分离**：内容融合与渲染执行分岗；渲染代理必须"先核实再执行"存疑指令；改图前备份整卡（可逐字节恢复）。

## 十、经验坑位（省时间清单）

1. grep 检查前先确认目标文件已 read（编辑器策略要求）。
2. 定位编译产物与源码**都要改**（lib/*.js 是运行时实际加载，src/*.ts 是源码一致性）。
3. 上游 API 排障顺序：`/me` 验身份 → 目录类只读端点 → 数据端点；HTTP 状态+body error 字段分开看（404 可能只在 POST，GET 存在）。
4. "成功但无数据"先怀疑展示层渲染函数（只渲染截断场景），再怀疑传输层。
5. 服务端进程内补丁需重启生效（DSH 桌面启动器「重启」按钮，会话可恢复）；重启回来先跑一次只读调用验证。
6. pptfast ending 型页只允许末位、subheading 单行容量；超 bullets 上限拆块重组。
7. 双列数字条用 flex 不用 grid（weasyprint 列宽塌陷）。
