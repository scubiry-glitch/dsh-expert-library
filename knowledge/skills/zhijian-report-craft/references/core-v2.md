# 工艺依据与适用范围

优先级：当前用户要求与任务契约 → 本包短规范 → 选定样式的组件 → 历史示例。例文中的日期、业务数字、观点和旧实现缺陷不构成本轮事实。材料加载、检查、审核不是扩大任务或外部发布权限的理由。

开始前记录主样式 `credit-policy` 或 `designer-paper`，如借用另一风格的组件，列出组件 id 与用途，不能混用互相矛盾的页面规则。两种样式均要求响应式 HTML；A4 只约束打印/PDF，不得把 794px 固定画布当手机网页。正文页按 i/N 连续计数，N 只含正文；封面和封底无页码，最终 PDF 必须保留章节大纲。

报告先生成可审草稿，再由当前版本的证据放行。机器结果仅覆盖已列检查；未运行、依赖不可用、证据过期或未知均是 unverified，不是 passed。不适用必须在冻结契约中有范围依据，不能在失败后取消必需项。无 PPT 要求则不启用 PPT 门禁；不按历史例文篇幅强制页数。

报告任务声明 `reportBundle={md,html,pdf,craftEvidence,materialPackId,materialDigest,style}`，使用 Host 给出的 v2 身份与声明的发布名。三件套、craftEvidence 和审核必须绑定同一次 task/attempt 的实际字节。任何正文、CSS、PDF 后处理或成品变化都会使旧证据过期；更新哈希、重跑适用检查并重新审核后才可交付。旧截图/旧 PASS 不能认证新版本。

Host 管理的发布/审核/整合与 shell 复制不同；外部复制文件不自动获得“合格交付”身份。业务尚未通过质量验收时，生命周期结束也不得报告全部交付成功。
