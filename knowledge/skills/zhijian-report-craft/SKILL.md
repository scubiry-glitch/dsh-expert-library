# 智见研报工艺（zhijian-report-craft）

> 一句话：**行文有骨架、数据有纪律、发布有门禁**。本 skill 规定"怎么写、怎么用数、怎么过关"；结构与视觉样式见引用模板（§0）。
> 沉淀自《一场"角色重写"》v5.4 全流程（2026-08-29，五专家评审+三轮渲染迭代+一次通道修复实战）。

## §0 模板引用（先读）

动手前**必读**模板文件（结构与视觉样式的唯一权威）：

```
knowledge/skills/zhijian-report-craft/references/report-template-fivepiece-v1.md
```

（工作区副本：`<workspace>/knowledge/shared/report-template-fivepiece-v1.md`，两处内容一致，任读其一。）

模板包含：总体结构（总-分-总+卷首速览）、章节五件套骨架表、点睛图九类选型表、视觉 register（深青墨 #0e6a55+琥珀金 #a9741f，finesse 五轴）、封面封底范式、渲染管线图。本 skill 不重复其内容，只规定执行规则。

## §1 行文逻辑（怎么写）

1. **总-分-总闭环**：总论立三要素（如知情权/控制权/责任），总结必须回到三要素收口，并推出一个可脱离上下文传播的收束金句。
2. **五件套同构**：每章严格按模板骨架（金句定位→角色对照→条款依据→推论与数据→机会风险）；骨架是结构清晰性的来源，禁止章章异构。
3. **推论公式**：每条推论 = 条款/事实 → 二阶后果 → 数字锚。**无数字锚的推论不得进入正文**（要么补数据，要么降级为"待补观察项"）。
4. **边界钉死**：每个乐观判断后紧跟边界句（"收窄≠转正""个案≠全国""准入≠激励"）；每个悲观判断后给可对冲条件。
5. **金句纪律**：每章至少 1 句章眼金句；金句标准=可被引用、可被反驳、不含未标注的数字。
6. **去过程痕迹**：正文零版本号、零修订清单、零评审专家名/轮次；过程信息只在文末来源披露一行。
7. **命名纪律**：行业章不得以单一公司命名主体；公司只作案例参照，且必须加"参照不等于豁免"式限定。
8. **语言**：短句、断言、术语随手白话化；每个专业缩写首次出现时给白话解释。

## §2 数据要求（怎么用数）

1. **四级标注**（每个非引用数字必须落到一级）：`测算`（模型算，给参数）/ `估算`（量级推断）/ `研判推断`（分析性判断）/ `待补`（观察清单项）。
2. **溯源**：宏观数据带来源+指标代码（如 Wind EDB W1409719）；分城市注明统计局/地方局口径与更新滞后；合作数据源注明口径属性（internal/external、绝对量/指数化）。
3. **铁律：编数字比不回答更严重。** 数据不可得 → 如实标注"待补"并进观察清单，绝不编造、绝不"合理估算后不标注"。
4. **多源纪律**：一个主定量源（如 Wind），合作通道（如 zyt）作趋势性/补充性引用；两源冲突时在来源披露中显式说明，不得静默择优。
5. **量值脱敏**：委托方要求不公开绝对量值时，只保留趋势表述（"同比连续 N 个月为正"），并把绝对量值列入渲染禁例 token 清单（见 §3 门禁一）。
6. **数据底座前置**：正文动笔前先固化数据底座表（指标/最新值/关键变化/代码），后文所有引用必须与底座一致——改数只改底座一处，全文同步。

### §2.7 三通道引用约定（Wind / 政研通 zyt / beike）

**Wind CLI（主定量源）**
- 调用：`node scripts/cli.mjs call economic_data search_economic_indicator '{"question":"<自然语言问题>"}'`——**优先自然语言提问**；直接给指标代码可能后端错配（实例：S2707425 代码直查返回上证总市值），错配时换自然语言重试一次再放弃。
- 引用格式：正文标注 `（Wind EDB，<发布机构>，截至 <年-月/季度>）`，指标代码进文末来源披露（如 W1409719/S2707425/M0058005）。

**政研通 zyt（expert_provider_call，趋势性/补充源）**
- 能力地图（2026-08 实测）：`indicators.catalog` / `indicators.timeseries`（series）/ `batch-series` / `city.compare`（**GET**，POST 404）/ `geo.tree` / `policies` / `reports` 可用；`market-snapshot` 上游 500；派生指标（rent_sale_ratio 类）可能空序列=数据侧未交付，标注"待补"，**不是通道故障**。
- 引用格式：`（贝壳政研通口径，趋势性信号）`；必须注明 dataView 属性——`internal`（对内版，绝对量）/ `external`（指数化，首值=100，**禁当绝对量**，信封自动加警告）。
- 凭据：`~/.config/zyt/config.json`（`{baseUrl, apiKey}`）；排障顺序：`/me` 验身份 → 只读目录端点 → 数据端点。
- **失败三态处理**：①调用报错→如实标"通道失败"；②返回成功但无数值→区分展示层/交付层，标注"待补"，不得编造；③部分指标空序列→如实写"该城该指标未交付"。

**beike CLI（房源/交易微观数据源）**
- 凭据：`~/.beike/BEIKE_MCP_API_KEY` 文件（缺失则 `listing.search` 等直接拒绝）。
- 未配置时：来源披露如实写"通道未配置"，**不得用其他源冒充贝壳口径**。

**三通道通用纪律**
- 来源披露逐通道一行交代状态：`已透出数值（本轮采用）/ 仅趋势性结论 / 待补 / 未配置`。
- 两源数值冲突：不得静默择优，在来源披露中显式说明差异与取舍。
- 每次调用带 `context`（任务/报告 id）留痕，审计可追溯。
- 发布前：所有外链 `curl -I` 验 200（含 PDF 附件链）。

## §3 质量要求（怎么过关：发布前五道门禁）

| 门 | 检查 | 通过标准 |
|---|---|---|
| G1 文字 | 禁例 token（量值脱敏清单/过程痕迹/错误命名）；品牌行、金句、章节标记逐项 grep | 禁例 0 命中；应有项 100% 在位 |
| G2 数字 | 交付物 vs md 关键锚点清单逐 token | 一致且零新增（锚点 28-70 项按报告规模） |
| G3 设计 | finesse 检测；playwright 1280/375 双视口；锚点；对比度 | P0=0；0 溢出/0 裁切/0 重叠；零死链；AA 0 失败 |
| G4 PPT | pptfast validate + audit；speaker notes | 双 0 findings；全页 notes |
| G5 PDF | 页数档位；页脚品牌+页码；章节大纲 | 逐页逐项命中（用 pypdf 验证，勿数原始字节） |

**执行方式**：把 G1 的禁例/应有清单写成 grep 循环脚本跑；G2 在 md 定稿时同步生成锚点清单；任何一门不过不得发布，修复后全门重跑（不是只重跑挂掉的门）。

## §4 渲染与发布流程

1. **md 唯一权威源**：所有修订只改 md；三件套（HTML/PDF/PPTX）一律从 md 重出，禁止手改成品文本。
2. **管线**：md → HTML（finesse register）→ PDF（weasyprint，封面封底 @page 命名页）→ PPTX（pptfast，seed=日期，全页 notes）→ sha256sums + shots/ → 发布。
3. **发布**：HTML 走 render_publish（slug 稳定，覆盖=同版本内容升级）；PDF/附件 `cp` 到 `/var/www/dsh-render/<团队id>/` 并 `curl -I` 验 200 后才给链接。
4. **版本协作**：一版一 slug，**绝不覆盖历史链接**；同版本迭代才允许同名覆盖。
5. **渲染岗分离**：内容融合与渲染执行分岗；渲染代理收到存疑指令必须"先核实再执行"；改图前整卡备份（保证可逐字节恢复）。
6. **门禁脚本化**：§3 五道门写成可重复执行的检查脚本（shots 目录随版重拍，作为门禁证据留存）。

## §5 快速检查清单（发布前最后过一遍）

- [ ] 卷首速览每行带关键数字；总纲金句在位
- [ ] 每章五件套齐全；每条推论有数字锚；每章有金句
- [ ] 每个非引用数字有四级标注之一；观察清单"待补"项口径注明
- [ ] 每个乐观判断后有边界句
- [ ] 正文无版本号/修订清单/专家名；行业主体未被单一公司命名
- [ ] 点睛图逐图核对：数字 md 在案 / 定性示意已标注 / 未披露期间已声明
- [ ] 封面数字全部 md 在案；封底免责在位；页码重排正确
- [ ] G1-G5 五道门全过；sha256 三件套校验 OK；shots 已重拍
- [ ] 发布链接 curl 200；历史版本链接未被覆盖
